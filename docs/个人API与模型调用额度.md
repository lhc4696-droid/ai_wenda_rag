# 个人 API 与模型调用额度

更新日期：2026-10-22。

## 当前规则

用户自己的 API 不再扣除项目提供的默认模型每日额度。普通聊天、流式聊天、编程任务中的每轮模型请求，以及“测试聊天 / 测试 Coding”均按实际使用的模型来源统计。切换同名模型也不会混淆来源；来源由后端适配器决定，不接受客户端指定。

| 调用来源 | 每账号每日额度 | 全站每日额度 | 统计 |
| --- | --- | --- | --- |
| 默认模型（服务器 Key） | 默认 100 次 | 默认 1000 次 | 默认模型次数、成功次数、已知 Token |
| 个人 API（用户 Key） | 不设默认模型日额度 | 不扣全站默认模型日额度 | 个人 API 次数、成功次数、已知 Token |
| 资料向量（服务器 Embedding Key） | 默认 100 个请求批次 | 默认 1000 个请求批次 | 单独记录次数、成功次数、已知输入 Token |

例：默认模型调用 30 次，个人 API 调用 120 次，账号页显示默认模型 30/100 次、个人 API 120 次。默认模型剩余 70 次。默认模型日额度耗尽后仍可使用个人 API，但如果服务器繁忙、触发频率限制或任务限制，仍会被暂停或拒绝。

个人 API 并不代表可以无限占用服务器。默认与个人 API 共用每用户分钟频率（默认 10 次）、每用户并发（默认 1 个）和全站并发（默认 4 个）；超时与上下文上限也保留。本地编程仍保留原有的独立每日任务数上限（默认每账号 20 个任务），一个任务中的多轮个人模型请求不扣默认模型额度。

所有来源中，已占额后失败、取消或超时的请求仍计入该来源统计；配额、登录或参数检查直接拒绝的请求不记为已受理调用。成功次数并不代表服务商只对成功请求收费，实际计费以对应模型服务商为准。次数统计是模型请求数，不是聊天条数或编程任务数。

## 资料问答

个人聊天 API 只替换生成答案的模型；文档和问题向量仍使用服务器的百炼 Key。

资料问答先原子检查并占用答案模型对应的额度和并发，再执行检索。默认模型额度已耗尽时，不会先发出收费的 Embedding 请求。个人 API 答案不受默认日额度限制，但每个真实 Embedding 批次都必须通过服务器独立预算。

一份尚未索引的短文档通常需要一个文档向量批次、一个问题向量批次；较长文档会拆成多个批次。已有索引可复用时，不重新生成文档向量，但新问题仍需要生成问题向量。向量额度耗尽后，后续批次在调用供应商之前被拒绝。

检索期间保持整轮聊天并发占用。Embedding 子调用使用独立的有界并发池，避免与自身父请求冲突；池大小和每用户分钟频率沿用 CHAT_USER_CONCURRENCY、CHAT_GLOBAL_CONCURRENCY 和 CHAT_REQUESTS_PER_MINUTE。取消、失败和超时均结束相关调用记录；不能保证供应商撤销已经产生的费用。

## 配置

不需要修改已有真实 `.env` 才能启用新规则。新增配置均有默认值，需要调整时再加入 `backend/.env`：

```dotenv
# 仅限制服务器默认答案模型
CHAT_REQUESTS_PER_DAY=100
CHAT_GLOBAL_REQUESTS_PER_DAY=1000

# 单独限制服务器 Embedding 的真实请求批次
RAG_EMBEDDING_REQUESTS_PER_DAY=100
RAG_EMBEDDING_GLOBAL_REQUESTS_PER_DAY=1000
```

日额度在 UTC 零点，即北京时间每天 08:00 重置；账号页按浏览器本地时区显示时间。修改环境配置后需重启后端。

## 统计接口与历史迁移

`GET /api/chat/usage` 的原有顶层 `requests`、`succeeded`、`input_tokens`、`output_tokens`、`daily_limit` 字段现在表示默认模型统计；新增 `custom` 与 `embedding`，结构与原统计一致。个人 API 的 `daily_limit` 为 null，表示不设项目默认模型日额度。`resets_at` 仍是 Unix 秒。

Token 汇总只累加供应商实际报告且通过格式校验的数字。个人兼容接口若未报告流式 usage，统计保留未知，不估算、不显示为零，也不会为补统计再次发起收费请求。Embedding 报告的 total_tokens 计入该来源的输入 Token；没有文本生成输出 Token。供应商未返回或失败时缺失的 Token 不代表没有费用。

数据库升级到版本 13，新增 `model_calls.source` 和来源/时间索引。新记录明确标为 default、custom 或 embedding。旧记录没有足够信息判断当时使用的 Key，原样保留并标为 legacy，当前日内暂归入默认模型额度；账号页提示旧调用数，次日不再影响新一天。不会依据当前个人设置或模型名称反推历史归属。

升级前备份 SQLite、附件及原有模型加密密钥。启动时自动执行迁移，不需要删库；开发模式的热重载也会执行启动迁移。本次自动化使用隔离数据库验证迁移与重复执行，随后只读检查发现本机现有数据库已经处于版本 13，运行中的后端也应核对是否已加载新代码。如需回退旧程序，应恢复与旧版本匹配的备份，不能让旧程序直接操作版本 13 的数据库。
