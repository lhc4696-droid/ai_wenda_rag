# 模型输出上限问题解决方案

## 问题现象

复杂问题时，模型回答被截断，提示"达到输出上限"。

## 问题根源

当前配置 `CHAT_MAX_OUTPUT_TOKENS=2048`，对于复杂问题不够用：
- 2048 tokens ≈ 3000-4000 汉字
- 代码示例 + 详细解释往往需要更多

## 解决方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|-----|------|------|---------|
| **方案1：提高 token 上限** | 简单直接，彻底解决 | 费用稍增，响应稍慢 | 推荐给所有用户 |
| **方案2：动态调整** | 按需分配，节省费用 | 需要代码改动 | 多租户平台 |
| **方案3：前端提示** | 不改后端 | 用户体验差 | 临时方案 |

## 方案 1：提高 token 上限（推荐）

### 修改配置文件

编辑 `backend/.env`：

```bash
# 原配置（太小）
CHAT_MAX_OUTPUT_TOKENS=2048

# 推荐配置（5倍提升）
CHAT_MAX_OUTPUT_TOKENS=8000

# 或更激进（接近上限）
CHAT_MAX_OUTPUT_TOKENS=8192
```

### 各模型的 token 上限

| 模型 | 最大输出 tokens | 建议配置 | 说明 |
|-----|----------------|---------|------|
| qwen-plus | 8192 | 8000 | 留一些余量 |
| qwen-max | 8192 | 8000 | 同上 |
| qwen-turbo | 8192 | 8000 | 同上 |
| gpt-3.5-turbo | 4096 | 4000 | OpenAI 限制 |
| gpt-4 | 8192 | 8000 | OpenAI 限制 |
| claude-3-sonnet | 4096 | 4000 | Anthropic 限制 |

### 重启生效

```powershell
# 停止后端（Ctrl+C）
# 重新启动
.\venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload
```

### 费用影响

**假设每次回答平均使用 5000 tokens**：
- 原配置（2048）：被截断，用户需要多问几次
- 新配置（8000）：一次回答完整，总费用可能更低

**通义千问计费参考**（以 qwen-plus 为例）：
- 输入：0.0004 元/千 tokens
- 输出：0.0012 元/千 tokens
- 8000 tokens 输出成本 ≈ 0.0096 元（不到 1 分钱）

## 方案 2：动态调整 token 上限

### 使用场景
- 多用户平台，不同用户不同配额
- 简单问题用小 token，复杂问题用大 token

### 实现思路

1. **增加用户级配置**
```python
# 在 user_model_settings 表增加字段
ALTER TABLE user_model_settings ADD COLUMN max_output_tokens INTEGER DEFAULT 8000;
```

2. **修改调用逻辑**
```python
# 从用户配置读取，而不是全局配置
max_tokens = user_settings.max_output_tokens or settings.chat_max_output_tokens
```

3. **前端控制**
```vue
<select v-model="maxTokens">
  <option value="2048">简洁回答（2048）</option>
  <option value="4096">标准回答（4096）</option>
  <option value="8000">详细回答（8000）</option>
</select>
```

## 方案 3：前端提示优化（临时）

### 不改后端，仅优化提示

在前端检测到 `answer_truncated: true` 时：

```vue
<div v-if="response.answer_truncated" class="warning">
  ⚠️ 回答已截断。建议：
  <button @click="continueQuestion">继续回答</button>
  <button @click="simplifyQuestion">简化问题</button>
</div>
```

## 推荐配置方案

### 个人开发/小团队使用

```bash
# backend/.env
CHAT_MAX_OUTPUT_TOKENS=8000
CHAT_CONTEXT_CHARS=80000  # 同时提高上下文预算
```

### 公开服务/成本敏感

```bash
# backend/.env
CHAT_MAX_OUTPUT_TOKENS=4096  # 平衡费用和体验
CHAT_CONTEXT_CHARS=60000
```

### 企业内部/不限费用

```bash
# backend/.env
CHAT_MAX_OUTPUT_TOKENS=8192  # 尽可能大
CHAT_CONTEXT_CHARS=100000
```

## 其他优化建议

### 1. 添加配置验证

在 `config_groups.py` 的 `ChatConfig.validate()` 中：

```python
def validate(self, system_prompt_length: int):
    # ... 现有验证 ...
    
    # 确保 max_tokens 不超过模型上限
    if self.max_output_tokens > 8192:
        raise ValueError("CHAT_MAX_OUTPUT_TOKENS 不应超过 8192（通义千问上限）")
```

### 2. 记录截断统计

在日志中记录被截断的次数，便于调整配置：

```python
if truncated:
    logger.info("answer_truncated request_id=%s length=%s tokens=%s", 
                identifier, len(content), result.output_tokens)
```

### 3. 给用户清晰提示

修改前端，当 `answer_truncated: true` 时：

```
您的问题较复杂，回答已达到长度上限。
建议：
1. 点击"继续"让 AI 接着回答
2. 将问题拆分成多个小问题
3. 联系管理员提高输出上限
```

## 验证改动

修改配置后，测试一个复杂问题：

```
请详细解释 Python 的装饰器，包括：
1. 基本概念和原理
2. 带参数的装饰器
3. 类装饰器
4. 多个装饰器叠加
5. 实际应用场景
每个部分都要有完整的代码示例和解释
```

**成功标志**：
- ✅ 回答完整，没有截断
- ✅ `answer_truncated` 字段为 `false`
- ✅ 日志显示 `output_tokens` 接近新上限

## 注意事项

1. **模型真实上限**：不同模型的 `max_tokens` 上限不同，查阅官方文档
2. **总 token 限制**：输入 + 输出不能超过模型的总上限（如 qwen-plus 是 32k）
3. **响应时间**：token 越多，生成时间越长，注意 `CHAT_TIMEOUT` 配置
4. **费用控制**：可以添加单次调用的费用上限告警

## 快速操作指南

**立即解决问题（5分钟内）**：

1. 打开 `backend/.env`
2. 找到 `CHAT_MAX_OUTPUT_TOKENS=2048`
3. 改为 `CHAT_MAX_OUTPUT_TOKENS=8000`
4. 重启后端
5. 测试复杂问题

完成！
