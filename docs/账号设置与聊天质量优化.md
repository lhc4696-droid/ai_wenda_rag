# 知言 AI：账号设置与聊天质量优化

日期：2026-09-16。接口版本：0.4.0。数据库结构版本：2。

后续更新：2026-09-17 的 0.5.0 已新增聊天历史，数据库结构版本为 3。改名、改密或退出登录均不会删除已保存的历史，详见 [聊天历史实现与验收](聊天历史实现与验收.md)。下文描述此前质量优化的配置与设计。

本轮实现个人账号设置与基础质量优化，不实现管理员后台、聊天历史、流式输出、邮箱更换或 Agent。按用户要求，本轮未运行功能测试；新增用例留待用户执行。

## 1. 个人账号设置

登录后使用右上角账号按钮打开菜单。电脑可悬停或点击，手机可点击；2026-09-17 起统一通过“账号设置”进入弹窗，再选择“账号资料 / 安全设置”，不再提供重复的修改密码快捷入口。模型回答期间账号设置暂时禁用，退出登录仍可操作。界面采用黑白灰底色与蓝色点缀，见 [聊天界面与账号交互调整](聊天界面与账号交互调整.md)。

- 查看当前用户名、已验证邮箱和当日调用次数。邮箱在这一版只读。
- 修改用户名仅需新用户名，不再要求输入当前密码。用户名为 1–32 个 Unicode 码点，支持中文、多语言文字、常用符号、内部空格和常见表情；首尾空白自动去除，拒绝纯空白、换行及不安全控制字符。英文字母 A–Z 不区分大小写且用户名不能重复。这是登录用户名，不是独立昵称。
- 改名不改变用户 ID，不撤销登录，不清空当前聊天；同源其他标签页会刷新资料。以后使用新用户名登录。
- 修改密码需要当前密码、新密码和确认密码。新密码为 8–128 字符，不能全部为空格，不能与当前密码相同。
- 主动改密不依赖邮件服务可用性。改密、撤销全部旧会话、创建当前浏览器新会话和使未使用的邮箱验证码失效，在同一事务中提交；向已验证邮箱尽力发送通知。
- 主动改密通过 HttpOnly Cookie 换发新凭证，当前浏览器及共享 Cookie 的标签页保持登录，其他浏览器或设备的旧登录失效。当前聊天和草稿不清空。邮箱找回密码仍撤销所有登录，不自动登录。无邮箱旧账号也能用当前密码主动改密，但仍不能邮箱找回。
- 敏感操作每用户 5 分钟最多 5 次，每连接 IP 5 分钟最多 20 次，包含成功与失败尝试；错误当前密码返回 400，不直接退出登录。
- 账号更新从登录会话取得用户 ID，不接受前端指定其他用户 ID；写事务内再次核对会话及认证版本，防止与退出、改密、密码重置发生竞态。

| 接口 | 字段或用途 |
| --- | --- |
| POST /api/auth/username | 2026-09-17 交互调整后只需 username；以当前登录会话确认身份，成功返回更新后的 user |
| POST /api/auth/password/change | current_password、new_password；成功换发 Cookie，当前浏览器保持登录、其他旧登录失效 |
| GET /api/chat/usage | 仅返回当前用户今日请求数、成功数、已知 Token 用量、额度与重置时间 |

## 2. 聊天保护与默认配置

以下配置均有默认值，无需重写真实 .env。要调整时参考 backend/.env.example，并在修改后重启后端。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| CHAT_TIMEOUT | 90 | 模型请求最长等待秒数，范围 5–100 |
| CHAT_CONTEXT_CHARS | 40000 | 系统提示与历史消息的总字符预算，范围 20000–200000 |
| CHAT_MAX_OUTPUT_TOKENS | 2048 | 模型最大输出 Token 数，范围 1–8192 |
| CHAT_REQUESTS_PER_MINUTE | 10 | 每用户滚动 60 秒内最多受理次数 |
| CHAT_REQUESTS_PER_DAY | 100 | 每用户每日最多受理次数 |
| CHAT_GLOBAL_REQUESTS_PER_DAY | 1000 | 全站每日最多受理次数 |
| CHAT_USER_CONCURRENCY | 1 | 同一用户同时进行的模型调用数量 |
| CHAT_GLOBAL_CONCURRENCY | 4 | 全站同时进行的模型调用数量 |

次数按成功占用额度的请求计算，包含后续失败、超时或取消，不自动退回；被限额拒绝的请求不消耗次数。每日额度按 UTC 零点重置，即北京时间 08:00，页面显示本地时间。Token 统计仅包含供应商已返回的已知用量，超时等请求可能未知，不能当作精确账单；供应商重试与计费规则以其服务为准。

限额和并发租约使用 SQLite 原子事务，共用同一个数据库文件的本机工作进程共享限制。异常退出后的租约在 CHAT_TIMEOUT + 30 秒后可回收；不支持多台服务器各用独立数据库的分布式限流。

后端使用 DashScope AioGeneration 异步接口，网络超时和业务超时均受 CHAT_TIMEOUT 限制；前端等待 120 秒，开发代理等待 125 秒。检测到客户端断开或超时会取消本地异步请求并关闭连接，不能保证供应商立即停止内部计算或计费。应用不自动重试。

上下文超出字符预算时，移除最早的完整轮次，保留当前问题和最近轮次，返回 context_trimmed=true。字符预算不是精确 Token 计数，不保证任意模型均能接受。若当前问题自身超过可用预算，提示缩短问题。

返回回答最多 20000 个字符；字符截断或模型因输出长度停止时返回 answer_truncated=true，页面明确提示。说明文字不混入下一轮模型输入。前端也约束历史回答长度，避免下一轮因历史消息过长返回 422。

## 3. 数据库与代码职责

新增 model_calls 表，仅记录用户 ID、模型名、请求编号、时间、耗时、状态、输入输出字符数、已知 Token 用量和错误类别，不保存问题、回答、密码、Cookie 或密钥，因此不是聊天历史。超过 30 天的记录在后续受理请求时清理。

sql/migrations/002_model_calls.sql 无损新增表，原有账号保留。迁移器按版本顺序执行，拒绝对更新版本数据库自动降级。启动时会迁移，也可以先备份再手动升级。

- backend/app/auth/account.py：当前密码核验与敏感操作流程。
- backend/app/auth/store.py：账号更新事务、会话撤销与验证挑战作废。
- backend/app/chat/service.py：上下文预算、超时、取消、回答边界与调用完成统计。
- backend/app/chat/store.py：额度、并发租约和调用元数据读写。
- backend/app/integrations/llm.py：异步 DashScope 适配与脱敏错误映射。
- backend/app/observability.py：请求关联编号与不含正文的日志。
- frontend/src/components/AccountSettings.vue：个人账号设置弹窗。
- frontend/src/lib/account-validation.js：注册与设置页共用校验。

## 4. 错误排查

每个请求返回 X-Request-ID；分类错误返回 X-Error-Code，限流返回 Retry-After。前端服务端错误提示包含排查编号，终端可按编号查日志。后台邮件日志包含请求编号、验证码记录编号和错误类别，不记录实际验证码或授权码。

| 错误类别 | 检查方向 |
| --- | --- |
| SMTP_PLACEHOLDER_HOST | SMTP_HOST 仍是 example.com 示例地址 |
| SMTP_AUTH_FAILED | 邮箱 SMTP 授权码或账号凭据 |
| SMTP_DNS_FAILED | SMTP 域名与 DNS |
| SMTP_TIMEOUT / SMTP_CONNECTION_FAILED | 网络、端口、服务可用性 |
| SMTP_TLS_FAILED | TLS、证书与端口加密方式 |
| SMTP_RECIPIENT_REJECTED / SMTP_SENDER_REJECTED | 收件人或发件人被拒绝 |
| LLM_AUTH_FAILED / LLM_REQUEST_REJECTED | 模型权限、模型名称或请求参数 |
| LLM_TIMEOUT | 模型未能在配置时间内完成 |
| CHAT_RATE_LIMIT / CHAT_DAILY_LIMIT | 个人调用次数达到限额 |
| CHAT_USER_BUSY / CHAT_SERVER_BUSY | 个人或全站并发达到上限 |

202 仍只表示验证码请求已受理，不代表收到邮件。SMTP 已确认接受邮件后，单独的 QUIT/关闭连接失败不再把验证码误标为失败；对于“服务器是否接受都未确认”的网络异常，仍保守标为失败。

## 5. 用户手动验收

本轮仅完成 Python、JavaScript 语法检查及 Vue 单文件组件静态编译检查；未执行下列功能测试，也未运行构建、真实邮件或模型联调。建议先保留当前配置和数据库备份，再重启后端并刷新前端。

```powershell
cd D:\code\project_python\wen_da
.\venv\Scripts\python.exe backend\migrate_db.py --backup
.\venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload
```

旧服务占用 8000 时，先在原窗口 Ctrl+C 停止；前端在另一窗口进入 frontend 后执行 pnpm dev。已安装的 DashScope/aiohttp 版本写入 requirements.txt，新环境按文件安装依赖。

1. 登录后打开设置；仅输入新用户名即可改名，聊天与登录保留；无效或重复用户名不能保存。安全设置中输入错误当前密码仍不能改密。
2. 退出后确认旧用户名不能登录，新用户名可以；重复用户名与非法用户名有清晰提示。
3. 在第二个浏览器也登录，主动改密后确认操作浏览器保持登录、聊天和草稿保留，另一个浏览器下一次请求返回未登录；当前浏览器的旧令牌也失效，新密码可登录，旧密码不可用。邮箱找回仍要求全部重新登录。
4. 确认 7 位密码拒绝、8 位接受、全空格和两次输入不一致被拒绝。
5. 同一账号并行提问，观察 429 和重试倒计时；可暂时降低 CHAT_REQUESTS_PER_MINUTE 验证频率限制，之后恢复。
6. 连续发送较长内容，确认上下文裁剪、回答长度提示与继续追问。
7. 按 X-Request-ID 和终端错误类别定位失败，截图不要包含 .env 密钥。

已编写后端账号、并发、上下文、模型适配、SMTP 分类回归用例，以及前端账号 API、状态逻辑和桌面/手机设置页用例。测试应用采用独立 Settings、临时数据库和模拟服务，并阻止外部连接（本机事件循环连接除外）。本轮未执行这些用例，不代表已通过。

正式部署仍需另行配置 HTTPS、可信代理与请求体大小限制、稳定发件服务、备份恢复。本文记录的 0.4.0 阶段尚未实现历史记录；2026-09-17 已在 0.5.0 中补充，详见《聊天历史实现与验收》。管理员、流式输出与 Agent 继续留待后续需求。
