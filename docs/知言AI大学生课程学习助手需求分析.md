## 1. 项目概述

### 1.1 项目名称

知言 AI——大学生课程知识理解与个性化答疑平台。

### 1.2 一句话描述

知言 AI 是一个面向大学生的智能学习平台。学生可以围绕指定课程资料用自然语言提问，系统利用大语言模型理解问题、检索课程资料、生成有出处的个性化讲解，并通过追问、练习和错因诊断帮助学生真正掌握知识。

### 1.3 选题所属方向

本项目属于“教育辅助”方向，同时包含：

- 前端开发：账号页面、课程空间、对话式学习、资料来源展示、练习与学习报告；
- 后端开发：身份认证、课程资料管理、对话管理、知识检索、学习记录和接口服务；
- AI 应用开发：问题理解、检索增强生成、分层讲解、苏格拉底式引导、错因诊断及个性化学习建议。

AI 不是附加的聊天装饰，而是完成“理解学生问题—查找课程依据—组织针对性讲解—诊断知识薄弱点”这一核心业务链路的必要能力。

## 2. 项目背景与立项依据

### 2.1 真实场景

以学习《数据结构》《Python 程序设计》《计算机网络》等大学课程为例，学生课后常遇到以下情况：

1. 课件中的定义较抽象，学生知道结论但不理解推导过程；
2. 搜索引擎返回的信息很多，却不一定符合本校课程范围和教师讲法；
3. 同一个问题在不同基础的学生看来难点不同，统一答案缺少针对性；
4. 教师和助教无法随时回答大量重复问题；
5. 学生直接查看标准答案容易形成“看懂了”的错觉，却没有暴露真正的知识漏洞；
6. 复习资料、提问记录和错题分散，考前难以形成清晰的薄弱点清单。

具体使用示例：一名学生复习“二叉树遍历”时，对课件中的递归过程不理解。他选择《数据结构》课程后提问：“为什么这里先访问左子树？能结合课件例子一步一步讲吗？”系统应先从已授权课件中检索对应章节，再按照学生当前水平分步说明，并在回答末尾提出一道变式题。如果学生答错，系统继续判断是“递归调用顺序”还是“遍历规则”理解错误，并记录该知识点。

### 2.2 政策与行业依据

教育部等五部门发布的《“人工智能+教育”行动计划》提出研发智能学伴、支持学生个性学习，并强调以学生为中心配置学习资源。[教育部原文][1] 因此，围绕真实课程资料建设可解释、可追溯的智能学伴，具有明确的应用价值。

教育部等九部门《关于加快推进教育数字化的意见》同时要求规范人工智能进校园，并防范数据安全、信息茧房和依赖成瘾等问题。[政策原文][2] 这意味着本项目除了追求“能回答”，还必须满足隐私保护、内容可靠、适度使用和人工复核等要求。

UNESCO 的《生成式人工智能在教育和研究中的应用指南》主张以人为中心，重视数据隐私、年龄适宜性以及教育和伦理验证。[UNESCO 指南][3] 本项目据此将 AI 定位为“辅助学习和引导思考的工具”，而不是代替教师、替学生完成作业或给出不可质疑的结论。

## 3. 问题定义

### 3.1 核心问题

如何让大学生在教师无法实时辅导的课后场景中，基于可信课程资料获得符合个人基础的及时讲解，并通过持续追问和诊断将“得到答案”转化为“掌握知识”？

### 3.2 现有方式的不足

| 现有方式 | 主要不足 |
| --- | --- |
| 搜索引擎 | 信息来源分散，结果与课程范围不一定一致，学生需要自行筛选 |
| 普通通用聊天机器人 | 不了解本课程资料，可能生成看似合理但没有依据的内容 |
| 课程群提问 | 教师回复时间不确定，重复问题多，部分学生不愿公开提问 |
| 直接查看答案 | 缺少推理过程和针对性反馈，难以发现错误原因 |
| 纸质或零散电子笔记 | 无法自动归纳高频错题、薄弱知识点和复习优先级 |

### 3.3 拟解决的关键矛盾

- 大量个性化问题与有限教师答疑时间之间的矛盾；
- 通用模型知识面广与课程内容要求具体之间的矛盾；
- 快速获得答案与培养独立思考能力之间的矛盾；
- 个性化学习所需数据与学生隐私保护之间的矛盾。

## 4. 建设目标与成功标准

### 4.1 建设目标

1. 建立一个随时可用的课程问答入口，降低学生提问门槛；
2. 优先依据课程课件、讲义和教师提供的资料回答，并展示出处；
3. 根据学生要求和历史表现提供“简明解释、详细推导、举例说明、启发式提问”等不同讲解方式；
4. 通过小测、追问和错因分类形成个人薄弱知识点记录；
5. 为学生生成阶段性复习建议，同时让教师看到匿名化的共性难点；
6. 在回答不确定或资料不足时明确提示，而不是编造答案。

### 4.2 可量化成功标准

| 指标 | 验收目标 |
| --- | --- |
| 资料可追溯率 | 对课程事实性问答，回答中展示至少 1 个有效资料来源；无相关资料时明确提示 |
| 核心任务完成率 | 典型场景测试中，登录、选择课程、提问、查看来源、完成练习的成功率不低于 90% |
| 回答相关性 | 教师或课程负责人抽查测试问题，80% 以上回答达到“基本正确且与课程相关” |
| 诊断有效性 | 对预设错误样例，系统能在 80% 以上案例中识别到预设知识点或错误类别 |
| 交互反馈 | 用户发送问题后 1 秒内出现“正在分析/思考”状态 |
| AI 响应时间 | 在正常网络条件下，95% 的文本问答在 30 秒内返回完整结果 |
| 安全底线 | 未登录不能调用学习接口；越权访问他人课程记录的测试通过率为 100% |

以上指标为课程项目的验收目标，不代表已完成的线上服务等级承诺。

## 5. 目标用户与相关角色

| 角色 | 主要特征 | 核心需求 | 权限范围 |
| --- | --- | --- | --- |
| 学生 | 需要复习课程、解决疑问的大学生 | 快速提问、获得可靠讲解、练习巩固、查看薄弱点 | 使用已开放课程、管理本人对话和学习记录 |
| 教师/资料管理员 | 提供课程资料并关注共性问题 | 上传资料、维护知识范围、查看匿名化问题统计 | 管理本人课程及其资料，不查看无关个人内容 |
| 系统管理员 | 维护系统正常运行 | 用户与课程管理、日志审计、异常处理 | 系统配置与合规管理，不默认读取私密对话正文 |
| AI 模型服务 | 提供语言理解与内容生成能力 | 接收经过控制的上下文并返回结构化结果 | 无独立业务权限，不直接访问数据库 |

课程第一版以“学生”角色为主，教师端和管理员端可在后续迭代中实现。

- 主要顾虑：AI 是否会脱离课程资料、是否直接代做作业、课件版权是否得到保护。

## 8. 核心业务流程

### 8.1 课程答疑流程

1. 学生注册或登录知言 AI；
2. 学生选择一门课程，并选择“概念讲解、习题思路、复习总结”等学习任务；
3. 学生输入问题；后续版本可支持上传题目图片；
4. 后端验证登录状态、输入长度、课程访问权限和调用频率；
5. AI 模块识别问题意图，结合对话上下文改写成完整检索问题；
6. 知识检索模块从指定课程资料中召回相关片段并进行排序；
7. 大语言模型依据检索结果、学生偏好和教学提示生成回答；
8. 系统执行来源校验、敏感内容检查和格式整理；
9. 前端显示答案、参考资料、置信提示和建议追问；
10. 学生可以继续追问、要求换一种解释方式或进入随堂练习；
11. 系统记录经过必要最小化处理的学习结果，用于生成薄弱点和复习建议。

### 8.2 错因诊断流程

1. AI 根据当前知识点生成一道检查题；
2. 学生提交答案和必要的解题过程；
3. AI 将学生答案与知识要点、评分规则进行对照；
4. 系统把问题归为概念混淆、条件遗漏、推理错误、计算错误或表达不完整等类别；
5. AI 不立即泄露完整答案，而是先给出一条针对性提示；
6. 学生再次作答后，系统给出讲解，并把结果写入个人学习记录。

| BE-10 | 日志与审计 | 记录接口状态、模型耗时和异常；敏感字段脱敏 | P1 | 日志中不出现密码、会话令牌和完整 API Key |
| BE-11 | 教师管理接口 | 提供课程、资料和匿名统计接口 | P2 | 教师只能管理自己负责的课程 |

### 9.3 AI 应用功能需求

| 编号 | AI 能力 | 需求说明 | 优先级 | 验收要点 |
| --- | --- | --- | --- | --- |
| AI-01 | 意图识别 | 判断用户是在询问概念、求解题思路、总结资料、请求出题还是闲聊 | P0 | 常见意图测试准确率达到预设验收指标 |
| AI-02 | 上下文理解 | 将“那第二步呢”等省略式追问结合历史改写为可检索问题 | P0 | 多轮场景能保持课程与知识点一致 |
| AI-03 | 检索增强生成 | 从课程资料中检索证据后生成回答，而非仅依赖模型通用记忆 | P0 | 课程事实性回答带可验证来源 |
| AI-04 | 个性化讲解 | 根据学生选择、追问次数和掌握情况调整难度与表达方式 | P1 | 同一问题在不同模式下呈现明显不同的教学策略 |
| AI-05 | 启发式引导 | 对作业和练习优先给思路、分步问题和提示，避免直接代做 | P1 | 引导模式首轮不直接输出完整答案 |
| AI-06 | 错因诊断 | 分析学生答案中的知识漏洞并关联课程知识点 | P1 | 输出结构至少含结论、错因、提示和关联知识点 |
| AI-07 | 练习生成与反馈 | 基于已检索资料生成难度适中的题目和评分要点 | P1 | 题目不超出已选课程范围，答案有资料依据 |
| AI-08 | 不确定性处理 | 证据不足、问题含糊或模型不确定时主动澄清或拒绝下结论 | P0 | 无相关资料的测试不得伪造课件出处 |
| AI-09 | 学习画像摘要 | 根据结构化学习记录生成薄弱点和复习建议 | P2 | 报告可追溯到练习记录，允许用户删除 |
| AI-10 | 内容安全 | 识别违法、有害、隐私泄露和明显越界内容并安全响应 | P0 | 安全测试不返回被禁止内容，不泄露系统提示和密钥 |

阿里云百炼官方资料指出，检索增强生成可以把外部信息检索结果加入模型输入，从而补充大模型缺少的专有知识。[百炼知识库说明][4] 因此，本项目将课程资料检索设为 P0，而不是把“上传资料”做成只存文件、不参与回答的装饰功能。

## 10. 为什么 AI 是核心能力

| 核心任务 | 普通规则或数据库能否独立完成 | AI 的必要作用 |
| --- | --- | --- |
| 理解自然语言问题 | 难以覆盖口语、省略和不同表达 | 识别语义、意图和上下文指代 |
| 匹配课程资料 | 关键词可初筛，但难处理同义表达和跨段关系 | 生成语义向量、改写查询并辅助排序 |
| 个性化讲解 | 只能返回固定模板 | 根据学生基础动态组织例子、步骤和语言 |
| 连续追问 | 固定问答库难理解上下文 | 结合历史识别“这里、上一步、换个例子”等指代 |
| 错因诊断 | 客观题可以规则判分，主观过程难以穷举 | 分析自然语言解题过程并归纳错误类型 |
| 生成针对性练习 | 人工题库只能按标签抽题 | 根据当前薄弱点生成变式题和分步提示 |

如果移除 AI，本系统只能成为课程资料搜索和笔记管理工具，无法完成自由提问、个性化讲解、主观错因诊断等核心价值。因此 AI 直接决定了项目能否解决目标问题。

## 11. 数据需求

### 11.1 主要数据实体

| 实体 | 关键字段示例 | 用途 |
| --- | --- | --- |
| 用户 | 用户编号、用户名、密码哈希、创建时间 | 账号和身份识别 |
| 会话 | 会话编号、用户编号、课程编号、标题、时间 | 管理多轮学习对话 |
| 消息 | 消息编号、会话编号、角色、内容、模型、时间 | 还原上下文和问题过程 |
| 课程 | 课程编号、名称、负责人、状态 | 隔离不同知识范围 |
| 课程资料 | 资料编号、课程编号、文件名、版本、授权信息 | 管理知识来源 |
| 资料片段 | 片段编号、资料编号、页码、正文、向量 | 检索和来源追溯 |
| 知识点 | 知识点编号、课程编号、名称、前置关系 | 组织学习内容 |
| 练习记录 | 用户、知识点、题目、作答、结果、错因 | 形成学习画像 |
| 模型调用记录 | 请求编号、耗时、状态、令牌用量、错误类型 | 性能、成本和故障分析 |

### 11.2 数据规则

1. 密码只保存不可逆哈希，系统不得记录明文密码；
2. 会话令牌和 API Key 不写入前端代码和普通日志；
3. 用户数据、课程数据和模型调用数据通过编号关联，按最小权限访问；
4. 上传资料前需确认版权或使用授权，并记录来源与版本；
5. 用户可以删除本人历史对话和学习记录；
6. 用于教师统计时优先采用汇总数据，不显示可识别学生身份的对话正文；
7. 数据保存期限、删除机制和备份策略需要在上线前明确；
8. 不把学生对话默认用于训练外部模型。

## 12. 非功能需求

### 12.1 性能与可用性

- 登录、课程列表、历史记录等普通接口在正常负载下 95% 于 2 秒内完成；
- AI 请求提交后 1 秒内给出界面状态反馈，完整回答目标见 4.2；
- 模型服务不可用时返回明确错误，并允许用户重试或保留问题；
- 同一请求应具备防重复提交措施，避免重复回答和重复计费；
- 后端需要设置超时、最大消息长度、最大对话轮数及单用户调用频率。

### 12.2 安全与隐私

- 所有学习接口必须校验登录状态和资源归属；
- 状态变更接口检查可信来源，降低跨站请求风险；
- 输入、输出和上传文件均需进行格式、大小和安全校验；
- 页面不得直接执行模型输出的 HTML 或脚本；
- 传输正式上线时使用 HTTPS，Cookie 设置 HttpOnly、Secure 和合理的 SameSite 属性；
- 对登录尝试和模型调用实施频率限制；
- 数据处理遵循必要、明确、最小化原则。《个人信息保护法》明确规定自然人的个人信息受法律保护。[法律原文][5]

### 12.3 可靠性与可维护性

- 前后端接口使用稳定的数据结构并提供版本管理；
- AI 服务通过统一适配层调用，便于更换模型或使用模拟模型测试；
- 关键模块应具备单元测试，注册登录、连续追问等核心流程具备端到端测试；
- 模型提示词、模型名称、课程检索参数使用配置管理，不散落在业务代码中；
- 记录可观测指标，包括请求量、错误率、AI 延迟和低置信回答比例。

### 12.4 易用性与兼容性

- 页面适配桌面与手机，表单、按钮和错误信息清晰可见；
- 支持 Enter 发送、Shift+Enter 换行，并兼容中文输入法；
- 等待、失败、超限、断网和登录过期都有明确反馈；
- 对重要图标提供文字或无障碍标签，保证键盘可完成核心操作；
- AI 回答必须清楚区分“课程资料中的事实”“模型解释”和“不确定内容”。

## 13. 业务规则与边界

### 13.1 业务规则

1. 学生必须登录后才能调用 AI；
2. 每次课程问答必须绑定一门课程，普通闲聊可进入单独的通用空间；
3. 课程事实性结论优先使用当前启用版本的资料；
4. 检索不到证据时，系统应说明“课程资料中未找到直接依据”，可以给出通用解释，但必须明确区分；
5. 引导学习模式下，作业类问题优先提示思路，不在第一轮直接输出可提交的完整作业；
6. AI 的评价属于学习反馈，不替代教师正式评分；
7. 教师停用或更新资料后，新回答不得继续引用已停用版本；
8. 用户达到对话轮数或调用频率上限时，系统提示新建对话或稍后再试。

### 13.2 项目范围内

- 大学生课程文本资料的智能问答；
- 多轮追问和个性化讲解；
- 有出处的检索增强回答；
- 基础练习、错因诊断和学习建议；
- 账号、课程、资料和学习记录管理。

### 13.3 项目范围外

- 替代教师进行正式考试和最终成绩评定；
- 自动完成并代交课程作业、论文或考试答案；
- 医疗、法律、投资等高风险专业决策；
- 未经授权抓取或公开传播受版权保护的课程资料；
- 第一版本中的复杂语音课堂、实时视频教学和大规模学校教务系统集成。

## 14. 当前项目基础与需求差距

根据当前代码检查，项目并非从零开始，已经具备可运行的前后端和 AI 对话基础。

| 模块 | 当前已具备 | 为本场景仍需补充 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite；注册/登录；响应式聊天界面；多轮追问；Markdown；复制、重试、新建对话 | 课程选择、来源卡片、资料上传、练习、错题本、学习报告和历史持久化 |
| 后端 | FastAPI；健康检查；注册、登录、退出；安全 Cookie；请求来源检查；SQLite 账号数据；对话接口 | 课程与权限模型、资料解析、向量检索、来源返回、对话与学习记录接口 |
| AI | 通过 DashScope 调用通义千问；系统提示词；多轮消息输入；模型异常处理 | 教育场景提示词、意图识别、RAG、分层讲解、错因诊断、练习生成和置信控制 |
| 测试 | 后端接口与认证测试；前端逻辑和浏览器端到端测试 | 课程越权、资料检索正确性、来源一致性、提示注入和教育场景评测集 |

当前系统每次由前端携带完整消息历史，聊天记录刷新后清空；这适合作为原型，但不满足学习档案和历史复习需求。后续需要后端持久化，同时限制传入模型的上下文长度。

## 15. 技术可行性

### 15.1 可复用技术基础

- 前端：现有 Vue 3 组件和响应式页面可以继续作为学生端；
- 后端：现有 FastAPI 接口、依赖注入和身份认证可扩展为课程服务；
- AI：现有 DashScope/通义千问适配层可以继续负责生成式问答；
- 数据库：SQLite 适合单机课程演示；若多用户并发和资料规模扩大，可迁移到 PostgreSQL，并增加向量存储；
- 测试：现有 Pytest、Node Test 和 Playwright 可以继续覆盖新增流程。

### 15.2 建议的 AI 处理链

用户问题 → 意图识别与查询改写 → 按课程过滤资料 → 语义/关键词混合检索 → 结果重排 → 组装课程证据与教学提示 → 通义千问生成 → 来源一致性检查 → 输出回答、来源与学习标签。

阿里云百炼的官方文档已经提供多轮对话和知识库能力说明，可作为现有模型接入与后续 RAG 实现的技术参考。[多轮对话文档][6]

## 17. 验收场景

### 17.1 正常课程问答

- 前置条件：学生已登录并有权访问《数据结构》课程；
- 操作：选择课程，询问“二叉树先序遍历为什么先访问根节点？”；
- 预期：系统返回清晰讲解，显示对应课件章节或页码，允许继续追问。

### 17.2 上下文追问

- 操作：学生接着问“那换成中序呢？”；
- 预期：系统识别“中序”仍指二叉树遍历，不要求学生重述全部背景。

### 17.3 资料不足

- 操作：询问课程资料完全没有涉及的内容；
- 预期：系统不得伪造课件名称或页码，应说明未找到课程依据，并询问是否需要通用解释。

### 17.4 引导学习

- 操作：学生在引导模式中粘贴一道课后题并要求答案；
- 预期：第一轮先拆解条件并给提示；学生作答后再针对错误环节反馈。

### 17.5 权限与隐私

- 操作：未登录调用对话接口，或学生尝试读取他人的会话编号；
- 预期：分别返回未登录或无权限错误，响应中不泄露他人数据。

### 17.6 模型故障

- 操作：模拟模型服务超时或返回异常；
- 预期：界面保留学生问题，显示可理解错误，并允许重试；后台记录脱敏异常。

## 18. 风险分析与应对措施

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 模型幻觉 | 学生记住错误知识 | 使用 RAG、显示来源、设置低置信提示、建立教师评测集 |
| 伪造来源 | 用户误以为内容来自课件 | 来源必须来自检索结果并可反查，禁止模型自由编写引用 |
| 过度依赖 AI | 学生弱化独立思考 | 默认提供思路和检查问题，设置引导模式与适度使用提醒 |
| 隐私泄露 | 学生对话或账号信息暴露 | 数据最小化、权限隔离、脱敏日志、删除机制和 HTTPS |
| 课程资料版权 | 未授权传播课件 | 上传时确认授权，资料仅对课程成员开放，禁止公开下载 |
| 提示注入 | 用户诱导模型泄露系统提示或跨课程资料 | 输入隔离、课程级检索过滤、输出检查，不把密钥放入提示词 |
| 模型服务故障 | 核心问答不可用 | 超时、重试、熔断、友好降级和故障日志 |
| 调用成本失控 | 项目无法持续运行 | 轮数/字数限制、缓存适合缓存的结果、模型分级和用量统计 |
| AI 代写作业 | 违背教学目的 | 识别作业语境、先提示后讲解、保留教师设置的课程规则 |

生成式 AI 服务在准确性、可靠性、知识产权和个人信息权益方面有明确治理要求，可参照《生成式人工智能服务管理暂行办法》落实。[管理办法原文][7]

## 19. 结论

“知言 AI 大学生课程知识理解与个性化答疑平台”面向真实、频繁且具有明确痛点的课后学习场景。项目现有代码已经完成前端、后端和通用大模型对话的基础闭环，进一步加入课程资料检索、来源展示、引导式讲解和错因诊断后，可以从“通用聊天工具”升级为“课程智能学伴”。

该方案同时满足作业要求的三部分开发内容：前端负责学习交互，后端负责账号、课程、资料和数据服务，AI 负责无法由固定规则替代的问题理解、知识检索、个性化讲解与诊断。AI 贯穿核心业务流程，属于解决问题的关键能力，而不是装饰性功能。
