# 新电脑环境搭建与项目迁移指南（Windows）

适用项目：知言 AI / `ai_wenda_rag`。根据 2026-09-21 的项目代码整理，面向几乎没有开发环境的新电脑。

目标：从 GitHub 拉取代码，在新电脑重建开发环境、补齐本地配置，然后继续使用 PyCharm 编写项目。

本文只讲本地开发环境，不是公网部署教程。操作命令使用 **PowerShell**；除明确写了“进入 frontend”的步骤外，都在项目根目录执行。本文没有替你运行测试、安装软件、迁移数据或推送代码。

## 1. 先理解：Git 带走代码，不会自动带走整个开发环境

| 内容 | Git 拉取后有吗 | 新电脑怎么处理 |
| --- | --- | --- |
| `backend/app/`、`frontend/src/` 等业务源码 | 有，前提是旧电脑已提交并推送 | 直接使用 |
| `backend/requirements.txt`、`backend/requirements-dev.txt` | 有 | 根据它们重新安装 Python 依赖 |
| `frontend/package.json`、`frontend/pnpm-lock.yaml` | 有 | 根据它们重新安装前端依赖 |
| `.env.example`、SQL 脚本、文档 | 有 | 作为配置模板和建库依据 |
| 根目录 `venv/` | 没有，已忽略 | 新电脑重新创建，不复制旧虚拟环境 |
| `frontend/node_modules/` | 没有，已忽略 | 用 pnpm 重新安装 |
| `backend/.env` | 没有，已忽略 | 安全迁移旧文件，或重新创建并填写 |
| `frontend/.env.local` | 没有，已忽略 | 默认不需要；改过代理地址才恢复 |
| `backend/data/` | 没有，已忽略 | 想保留账号、历史和附件时单独迁移 |
| `.idea/`、`.vscode/` | 没有，已忽略 | 重新选解释器、设置运行配置 |
| Git、Python、Node.js、pnpm、PyCharm | 不属于项目源码 | 新电脑分别安装 |

**只拉取仓库，通常不能直接运行，这是正常的。** 代码、依赖、密钥配置和用户数据是不同的东西。

## 2. 离开旧电脑前，要准备什么

### 2.1 确认最新代码真的推送成功

“提交”只把代码保存在旧电脑的本地 Git 仓库；“推送”才会上传到 GitHub。

你之前遇到过 `SSL_ERROR_SYSCALL` 推送失败，所以换电脑前要在 GitHub 网页确认：最新一次提交、你新加的文件，以及本指南已经出现在远程仓库中。推送失败时，不要误以为新电脑能拉到本地尚未上传的内容。

提交前检查变更列表，不要上传真实密钥和数据。本文不会自动为你提交或推送。

### 2.2 单独保管配置和数据

根据需要准备以下内容：

- `backend/.env`：模型密钥、邮件服务凭据、验证码密钥等。
- `frontend/.env.local`：仅当你修改过默认后端代理地址时需要。
- `backend/data/` 整个目录：如果要保留原来的项目账号、聊天历史和上传附件。
- GitHub 登录方式、邮箱 SMTP 授权码的取得方式，以及百炼控制台的访问权限。

真实配置和数据通过可信、受保护的方式迁移，例如加密存储或受控的本地拷贝，不要放进公开仓库、公开聊天或截图。

如果只想在新电脑从空数据库开始，可以不迁移 `backend/data/`；之后需要在项目网页重新注册账号。GitHub 账号与项目里的聊天账号不是同一个系统。

**迁移数据库前，先停止旧电脑的后端，包括 PyCharm 中运行的进程。** SQLite 使用 WAL，不要在后端仍写入时只复制一个 `zhiyan.sqlite3` 主文件。停止相关进程后保留并复制整个数据目录，不要自行删除其中的 WAL 文件。恢复步骤见第 8 节。

如果旧 `.env` 中设置了自定义 `AUTH_DB_PATH`，数据可能不在默认目录；应备份实际数据库及其旁边的 `attachments` 文件夹。

## 3. 在新电脑安装基础软件

以下版本选择以当前项目配置和旧环境记录为依据，不要求复制旧电脑上的绝对安装路径。

| 软件 | 本指南采用的选择 | 用途及官方入口 |
| --- | --- | --- |
| Git for Windows | 官方当前稳定版 | 拉取、提交和推送代码：[Git 下载](https://git-scm.com/downloads/win) |
| Python | Python 3.13 系列的维护版本 | 后端运行环境：[Windows 下载](https://www.python.org/downloads/windows/) |
| Node.js | Node.js 22 系列的维护版本，至少 22.12 | 前端开发环境：[Node.js 下载](https://nodejs.org/en/download) |
| pnpm | `10.33.0` | 与当前 `package.json` 的 `packageManager` 保持一致 |
| PyCharm | 安装后打开项目根目录 | 编写代码、选择解释器、启动后端：[PyCharm 下载](https://www.jetbrains.com/pycharm/download/) |

补充说明：

- 旧电脑的 `venv/pyvenv.cfg` 记录为 Python 3.13.0。这里沿用 3.13 系列，不要求继续使用最早的 3.13.0 补丁版本，也没有声明已经验证所有 Python 版本。
- 前端当前声明的 Node 要求为 `^20.19.0 || >=22.12.0`。本文选择 22 系列作为统一安装路线，不必为此另外装多个 Node 版本。
- 使用与你电脑架构对应的安装包；普通 Intel/AMD Windows 电脑通常选 x64。
- Python 安装时保留 pip，并确保可以调用 Python/`py`；传统安装器中可勾选 `Add python.exe to PATH`。Node.js 安装时保留 npm 和 PATH 配置。
- 安装后重新打开 PowerShell；如果 PyCharm 已打开，也要重启，让它读取更新后的 PATH。
- 当前项目使用 SQLite，**不需要另外安装 MySQL、PostgreSQL、Redis、Docker 或本地大模型**。SQLite 由 Python 提供，模型通过后端访问百炼。

打开新的 PowerShell，查看版本：

```powershell
git --version
py -3.13 --version
node --version
npm.cmd --version
```

如果 `py` 找不到，但 `python --version` 确认为已安装的 Python 3.13，可以在后面创建虚拟环境时使用 `python -m venv venv`。不要在不确认版本的情况下使用另一个旧 Python。

然后安装项目要求的 pnpm：

```powershell
npm.cmd install --global pnpm@10.33.0
pnpm.cmd --version
```

这里使用 `npm.cmd`、`pnpm.cmd`，是为了避免之前 PowerShell 禁止执行 `pnpm.ps1` 的问题，不需要为了启动项目全局放开脚本执行策略。pnpm 的安装方式见[官方说明](https://pnpm.io/installation)。

## 4. 从 GitHub 拉取项目

以下示例继续使用旧电脑的项目路径：

```text
D:\code\project_python\wen_da
```

新电脑没有 D 盘也没关系，可以改用 `C:\code\wen_da` 等位置；后文所有完整路径相应替换即可。项目不依赖必须安装在 D 盘。

在 PowerShell 执行：

```powershell
New-Item -ItemType Directory -Force -Path D:\code\project_python
Set-Location D:\code\project_python
git clone https://github.com/lhc4696-droid/ai_wenda_rag.git wen_da
Set-Location .\wen_da
git status
git branch --show-current
git remote -v
```

注意：

- `git clone` 是首次下载；已有完整仓库后，更新使用 `git pull`，不要反复克隆到同一目录。
- 目标 `wen_da` 如果已经存在且有文件，先确认内容，不要直接删除或覆盖。
- 当前旧电脑分支为 `master`。如果远程默认分支以后变了，以实际仓库为准。
- 新电脑通过普通 `git clone` 得到的远程名称通常是 **`origin`**。本次查看旧电脑时，其远程名实际为 **`gihub`**，不要把旧电脑的远程名称直接套到新电脑。
- 私有仓库需要先完成有权限的 GitHub 身份认证。Git 提交用户名不等于 GitHub 登录凭据，不要把令牌写入远程 URL 或本文。

拉取成功后，看到 `backend`、`frontend`、`docs` 和根目录 `README.md`，这个 `wen_da` 文件夹就是**项目根目录**。不要把 `backend/app` 当成整个项目根目录。

## 5. 重建 Python 虚拟环境和安装后端依赖

在项目根目录执行：

```powershell
Set-Location D:\code\project_python\wen_da
py -3.13 -m venv venv
.\venv\Scripts\python.exe -m pip install --upgrade pip
.\venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
```

`requirements-dev.txt` 已引用 `requirements.txt`，这一次安装包含运行依赖和开发依赖；安装开发依赖不等于执行测试。只需要运行项目时，也可以选择安装 `backend/requirements.txt`。

之后本项目使用的 Python 是：

```text
D:\code\project_python\wen_da\venv\Scripts\python.exe
```

**不需要先激活虚拟环境**，本文始终显式调用这个解释器，因此也不会遇到激活脚本 `Activate.ps1` 被禁用的问题。Python 官方说明：虚拟环境应在目标电脑重新创建，而不是直接移动旧环境，见 [venv 文档](https://docs.python.org/3.13/library/venv.html)。

如果根目录已经有 `venv/`，先确认是不是在新电脑刚创建的有效环境；不要把旧电脑拷来的虚拟环境当成可直接复用的环境，也不要盲目覆盖不明目录。

## 6. 配置后端 `backend/.env`（关键步骤）

### 6.1 两种方式，只选一种

**方式 A：迁移旧配置。** 把安全保存的旧 `backend/.env` 放到新项目的 `backend/.env`。检查里面是否有旧电脑的绝对路径、失效凭据，或只适用于旧电脑的设置。

**方式 B：创建新配置。** 仅在文件不存在时，从模板复制：

```powershell
if (-not (Test-Path -LiteralPath .\backend\.env)) {
    Copy-Item -LiteralPath .\backend\.env.example -Destination .\backend\.env
}
```

然后在 PyCharm 中编辑 `backend/.env`。注意文件名不是 `.env.txt`，也不是放在项目根目录的 `.env`；当前后端明确读取的是 **`backend/.env`**。

**当前仓库的 `backend/.env.example` 没有列全 SMTP 和验证码配置。只复制它并填写模型密钥，还不足以完成新用户邮件注册。** 对照下面的完整配置补齐；已有配置不要整段覆盖，同名配置只保留一项。

### 6.2 完整的本地开发配置示例

以下均为示例或默认值，`REPLACE_WITH_...` 必须换成你自己的真实值。不要把真实配置回填进本文或 `.env.example`。

```dotenv
# ---------- 百炼 / 千问 ----------
DASHSCOPE_API_KEY=REPLACE_WITH_YOUR_DASHSCOPE_API_KEY
QWEN_MODEL=qwen-plus
# 可选：填写你的账号可用的视觉模型 ID；留空则禁用图片上传。
QWEN_VISION_MODEL=
SYSTEM_PROMPT=你是一个友好、准确的中文 AI 助手。回答应清晰、简洁；不确定时应明确说明。

# ---------- 本地前端来源 ----------
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173

# ---------- SQLite 和登录会话 ----------
# 相对路径以 backend 为基准，而不是以启动命令所在目录为基准。
AUTH_DB_PATH=data/zhiyan.sqlite3
SESSION_MAX_AGE=604800
# 本地使用 HTTP，保持 false；正式 HTTPS 部署另行配置。
SESSION_COOKIE_SECURE=false

# ---------- SMTP 发件配置 ----------
# 服务器、端口与加密方式必须按你的邮箱服务商填写。
SMTP_HOST=REPLACE_WITH_YOUR_SMTP_HOST
SMTP_PORT=465
SMTP_SECURITY=ssl
SMTP_USERNAME=REPLACE_WITH_YOUR_SMTP_USERNAME
SMTP_PASSWORD=REPLACE_WITH_YOUR_SMTP_AUTHORIZATION_CODE
SMTP_FROM=REPLACE_WITH_YOUR_SENDER_EMAIL
SMTP_TIMEOUT=10

# ---------- 邮箱验证码 ----------
# 用下方命令生成独立随机密钥，不要直接使用此占位符。
EMAIL_CODE_SECRET=REPLACE_WITH_A_GENERATED_RANDOM_SECRET
EMAIL_CODE_TTL=300
EMAIL_CODE_COOLDOWN=60
EMAIL_CODE_MAX_ATTEMPTS=5

# ---------- 模型请求保护 ----------
CHAT_TIMEOUT=90
CHAT_CONTEXT_CHARS=40000
CHAT_MAX_OUTPUT_TOKENS=2048
CHAT_REQUESTS_PER_MINUTE=10
CHAT_REQUESTS_PER_DAY=100
CHAT_GLOBAL_REQUESTS_PER_DAY=1000
CHAT_USER_CONCURRENCY=1
CHAT_GLOBAL_CONCURRENCY=4

# ---------- 附件 ----------
ATTACHMENT_MAX_BYTES=10485760
ATTACHMENT_USER_QUOTA=209715200
```

哪些值要自己准备：

| 配置项 | 怎么填写 |
| --- | --- |
| `DASHSCOPE_API_KEY` | 从自己的百炼账号取得，或安全迁移仍有效的旧密钥；不要填 GitHub 令牌 |
| `QWEN_MODEL` | 当前默认 `qwen-plus`；要确认你的服务地域、账号权限和额度支持所填模型 |
| `QWEN_VISION_MODEL` | 需要图片问答时填写可用视觉模型；不需要时留空，文字和文档问答不受这个开关影响 |
| `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURITY` | 按发件邮箱服务商说明填写；项目支持 `ssl` 和 `starttls`，常见组合分别是 465 和 587，不能任意混搭 |
| `SMTP_USERNAME`、`SMTP_PASSWORD`、`SMTP_FROM` | 发件账号、授权码/服务凭据、允许使用的发件邮箱；不是项目用户的登录密码 |
| `EMAIL_CODE_SECRET` | 服务器独立随机密钥，至少 32 字符；下面给出生成命令 |

如果是全新配置，在根目录执行下面的命令，将输出**只填入本地 `.env`**：

```powershell
.\venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
```

如果迁移了旧配置，原有 `EMAIL_CODE_SECRET` 可以保留，不需要每次启动重新生成；更换它会使尚未使用的旧验证码无法核验，但不会修改用户密码。

邮箱账号还需按服务商要求开启 SMTP、申请授权码或完成发件认证。填了 SMTP 字段不代表账号已经具备发件权限。

**没有 SMTP 配置，后端可能仍能启动，但新用户无法通过正常邮件验证码流程注册。** 如果同时使用全新空数据库，就没有旧账号可以直接登录，也没有默认管理员或默认密码。

`.env` 建议保存为 UTF-8。值包含空格或 `#` 等特殊字符时，按 dotenv 语法使用合适的引号，例如 `SMTP_PASSWORD="你的完整授权码"`。不要粘贴中文弯引号。修改配置后要停止并重启后端；PyCharm 运行配置或系统环境变量中的同名值可能优先于 `.env`，遇到配置未生效时一并检查。

## 7. 安装前端依赖及可选代理配置

进入前端目录：

```powershell
Set-Location D:\code\project_python\wen_da\frontend
pnpm.cmd install --frozen-lockfile
```

这会根据已提交的锁文件安装依赖。Vue、Markdown、KaTeX 等都已记录在项目依赖中，**不需要在新电脑再单独安装一次公式插件**，也不要改用 npm 安装项目依赖来混用锁文件。

若提示锁文件与 `package.json` 不一致，先确认拉取的是完整、匹配的提交，并核对 pnpm 版本；不要先删除锁文件或使用强制参数掩盖问题。后端有些依赖使用版本范围，因此本文是环境重建指南，不保证所有 Python 间接依赖与旧机器逐字节一致。

当前后端默认地址是 `http://127.0.0.1:8000`，Vite 已设置默认代理，**不用创建前端环境文件也能启动**。

仅当后端地址改变时，在当前 `frontend` 目录执行：

```powershell
if (-not (Test-Path -LiteralPath .\.env.local)) {
    Copy-Item -LiteralPath .\.env.example -Destination .\.env.local
}
```

编辑 `frontend/.env.local`：

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8000
```

如果后端改到 8001，这里也改成 8001，并重启前端。`API_PROXY_TARGET` 由 Vite 服务器读取。**模型 API Key、SMTP 凭据和验证码密钥只放后端，不放前端文件，不使用 `VITE_` 变量暴露给浏览器。**

## 8. 数据库：从空数据开始，还是保留旧数据

### 8.1 不保留原账号、聊天和附件

不用从旧电脑复制数据，也不用手工安装数据库服务。回到项目根目录，可显式初始化：

```powershell
Set-Location D:\code\project_python\wen_da
.\venv\Scripts\python.exe backend\init_db.py
```

后端启动时本来也会自动初始化/迁移，所以此步骤可以用于提前建库，并非每次启动都要执行。它不会创建默认账号；启动网页后自行注册。

### 8.2 保留原账号、聊天历史和附件

1. 旧电脑后端停止后，保存一份完整的数据目录备份，见第 2 节。
2. 新电脑先不要启动后端、不要创建新的聊天数据。
3. 把备份恢复到 `AUTH_DB_PATH` 对应的位置。使用默认配置时，就是把旧 `backend/data/` 放到新项目同名位置。
4. 数据库和 `attachments/` 必须来自同一份一致的备份。只复制数据库会留下附件记录但缺少文件；只复制附件则没有关联信息。
5. 如果新电脑同名位置已经有重要数据，先另存备份，不要直接覆盖；本文不包含两套数据库的合并操作。
6. 在根目录执行迁移，升级前自动另存数据库副本：

```powershell
.\venv\Scripts\python.exe backend\migrate_db.py --backup
```

当前代码的数据库结构版本为 4，后续版本应以仓库迁移脚本为准。不要向旧库手工执行整份新 `schema.sql` 来代替迁移，也不要把新版本数据库交给更旧的代码运行。

`--backup` **只备份 SQLite，不会备份附件目录**；完整迁移仍需要单独保管附件。恢复数据库后，原用户名和密码仍可用于登录；新电脑浏览器没有旧 Cookie，需要重新登录。

两个电脑各自使用本地 SQLite 时，后续聊天数据不会通过 `git pull` 自动同步。Git 负责代码同步，不负责数据库同步。

## 9. 在 PyCharm 中选择解释器和运行配置

### 9.1 打开整个项目

在 PyCharm 选择“打开 / Open”，选择 `D:\code\project_python\wen_da`，不是只打开 `backend/app` 或 `frontend`。

### 9.2 选择刚创建的虚拟环境

菜单名称会因 PyCharm 版本、界面语言不同略有变化，可以在设置的搜索框搜索 `Python Interpreter` 或“Python 解释器”。

1. 打开“文件 → 设置”（`Ctrl+Alt+S`）。
2. 找到当前项目的“Python 解释器 / Python Interpreter”。
3. 选择“添加解释器 → 添加本地解释器 / Add Local Interpreter”。
4. 选择现有环境，而不是再创建第二个虚拟环境；某些版本显示为选择已有 Python 或 `Select existing`。
5. 指定 `D:\code\project_python\wen_da\venv\Scripts\python.exe`。
6. 应用设置，等待 IDE 完成依赖索引。

重点是最终解释器路径正确，而不是菜单文字必须完全一致。官方入口说明见 [PyCharm 解释器配置](https://www.jetbrains.com/help/pycharm/configuring-python-interpreter.html)。

### 9.3 配置后端启动项

在“运行 → 编辑配置”里添加一个 Python 配置：

| 项目 | 填写内容 |
| --- | --- |
| 名称 | `backend`，也可以自定义 |
| Python 解释器 | 根目录 `venv\Scripts\python.exe` |
| 运行方式 | 模块名称 / Module name |
| 模块名称 | `uvicorn` |
| 参数 | `app.main:app --reload --host 127.0.0.1 --port 8000` |
| 工作目录 | `D:\code\project_python\wen_da\backend` |
| 环境变量 | 可保留 `PYTHONUNBUFFERED=1`；不必把密钥再复制到这里 |

这里选择的是 **module → uvicorn**。不要把 `python.exe` 填到“脚本路径”里：它是解释器，不是业务脚本。这里工作目录选 `backend`，所以参数不用再写 `--app-dir backend`。

后端自身会加载 `backend/.env`，通常不需要另外填写 IDE 的“.env 文件路径”。如果解释器一直加载，先确认文件路径确实存在且依赖已安装，再重启 IDE；不要通过切换到随机的全局解释器来掩盖问题。

## 10. 启动项目：两个终端分别运行

下面是与 PyCharm 运行按钮等价的命令行方式。两种后端启动方式选一种，不要同时占用 8000 端口。

**终端 A：在项目根目录启动后端。**

```powershell
Set-Location D:\code\project_python\wen_da
.\venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

也可在完成所有安装和配置后使用项目根目录的 `start_backend.bat`。它依赖根目录已有 `venv/`，不是自动安装环境的脚本。

**终端 B：启动前端。**

```powershell
Set-Location D:\code\project_python\wen_da\frontend
pnpm.cmd dev
```

保持两个终端运行。需要停止服务时，在对应终端按 `Ctrl+C`。

| 地址 | 用途 |
| --- | --- |
| <http://127.0.0.1:5173> | 实际使用的前端聊天网页 |
| <http://127.0.0.1:8000/api/health> | 后端健康接口 |
| <http://127.0.0.1:8000/docs> | 后端接口文档，不是聊天页面 |

为了避免 Cookie 混用，开发时统一用 `127.0.0.1`，不要一会儿用 `localhost`、一会儿换成 `127.0.0.1`。这两个地址上的浏览器登录态不是同一份。

打开页面后：空数据库走邮箱验证码注册；恢复旧数据库则用原账号登录。健康接口正常、页面显示“服务已连接”，只说明后端能访问，**不代表 SMTP、模型权限、余额和图片模型都配置成功**。

## 11. 之后每天继续开发，不用重装环境

首次配置完成后，平时只需启动上一节的两个服务。以下情况才重新安装依赖：

- Python 依赖文件变化：在根目录重新执行 `venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt`。
- 前端 `package.json` 或锁文件变化：在 `frontend` 重新执行 `pnpm.cmd install --frozen-lockfile`。
- 数据库迁移变化：先备份，再按第 8 节执行迁移。
- `.env` 内容变化：重启对应服务，不是重新创建虚拟环境。

新电脑第一次提交前，可以在此仓库配置提交者信息：

```powershell
git config user.name "你的提交显示名"
git config user.email "你选择的提交邮箱"
```

这两项仅用于提交署名，不会完成 GitHub 登录。可以使用自己 GitHub 账号提供的隐私邮箱，不必在公开提交中暴露私人邮箱。

两台电脑轮流开发时，建议：

1. 离开一台电脑前，检查修改、提交必要文件并确认推送成功。
2. 在另一台电脑开始前，先 `git status`，有未提交修改就先妥善保存。
3. 确认当前是预期分支后执行 `git pull --ff-only`。如果提示分支分叉或冲突，先处理，不要直接强制覆盖。
4. 根据变动更新依赖或本地配置。

新克隆仓库的远程若为 `origin`、当前分支仍是 `master`，推送命令是 `git push origin master`。如果实际名称不同，以 `git remote -v`、`git branch --show-current` 的结果为准。

## 12. 常见问题速查

| 现象 | 优先检查 |
| --- | --- |
| GitHub 克隆/推送报 `SSL_ERROR_SYSCALL` | 网络或代理连接；浏览器可访问不代表 Git 使用同一代理，不要关闭 SSL 证书校验作为常规解决办法 |
| `pnpm.ps1` 无法加载、禁止运行脚本 | 使用本文的 `pnpm.cmd` / `npm.cmd` 命令 |
| 找不到 Git、Python、Node、pnpm 命令 | 是否安装成功、PATH 是否生效；重新打开终端和 IDE |
| `No module named uvicorn` 或其他 Python 模块缺失 | 是否给当前项目的 `venv\Scripts\python.exe` 安装了依赖，PyCharm 是否选对解释器 |
| `Could not import module app.main` | 根目录启动必须带 `--app-dir backend`；在 PyCharm 中则按本文把工作目录设为 `backend` |
| 8000 / 5173 端口占用 | 是否已有终端或 PyCharm 启动了旧服务；先确认进程再关闭，不要随意终止不明进程 |
| 打开 8000 根地址返回 404 | 这不是聊天页；使用 5173，健康接口为 `/api/health` |
| 网页打开但“服务未连接” | 后端是否运行；前端代理是否指向实际后端地址 |
| 注册提示邮件服务未配置 | `backend/.env` 是否补全 SMTP 和随机 `EMAIL_CODE_SECRET` |
| 提示验证码已受理却没收到邮件 | 授权码、SMTP 权限、发件地址、垃圾邮件、收件邮箱；受理不等于投递成功，可查看后端脱敏错误类别 |
| 健康接口正常但聊天失败 | 模型 Key、权限、地域、所选模型、网络和额度；修改配置后重启后端 |
| 图片上传不可用，文字聊天正常 | `QWEN_VISION_MODEL` 是否配置；单配 `QWEN_MODEL` 不会启用图片功能 |
| 新电脑找不到旧账号或聊天记录 | 是否只拉了源码，没有恢复旧 SQLite；是否指向错误的 `AUTH_DB_PATH` |
| 历史中有附件但下载不了 | 是否只迁移数据库，没有迁移配套 `attachments/` |
| 修改 `.env` 后仍用旧值 | 重启后端/前端；检查 IDE 和系统环境变量是否另设了同名配置 |
| 本地登录后仍不保持会话 | 主机地址是否混用；本地 HTTP 下是否误设了 `SESSION_COOKIE_SECURE=true` |

排查错误时可以分享错误类别、文件位置和不含敏感信息的截图，**不要把完整 `.env`、API Key、SMTP 授权码、GitHub 令牌发到聊天或提交到仓库**。

## 13. 换电脑完成清单

- [ ] 旧电脑最新代码已真正推送到 GitHub，而不只是本地提交。

- [ ] 仓库已克隆，清楚自己的项目根目录、分支和远程名称。
- [ ] 根目录新建了 `venv/`，后端依赖已安装到此环境。
- [ ] `backend/.env` 已安全恢复或创建，模型、SMTP、验证码密钥配置完整。
- [ ] 前端已根据锁文件安装依赖，必要时配置 `frontend/.env.local`。
- [ ] 已明确选择“空数据重新开始”或“迁移数据库及附件”。
