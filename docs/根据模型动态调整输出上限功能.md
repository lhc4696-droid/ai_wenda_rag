# 根据模型动态调整输出上限功能

## 功能概述

新增功能：每个自定义模型可以配置自己的 `max_output_tokens`，不再受全局配置限制。

**解决的问题**：
- 不同模型的输出上限不同（GPT-4: 8192, Claude: 4096, 通义千问: 8192）
- 用户可以根据实际需求灵活调整
- 避免"模型输出达到长度上限"的错误

## 工作原理

### 优先级

```
用户自定义 max_output_tokens > 全局 CHAT_MAX_OUTPUT_TOKENS
```

### 代码逻辑

**使用默认百炼**：
```python
# 使用全局配置 settings.chat_max_output_tokens
provider = DashScopeLLM(settings)
```

**使用自定义模型（未设置 max_output_tokens）**：
```python
# profile.max_output_tokens = None
# 使用全局配置 settings.chat_max_output_tokens
provider = OpenAICompatibleLLM(settings, profile)
```

**使用自定义模型（设置了 max_output_tokens = 8000）**：
```python
# profile.max_output_tokens = 8000
# 使用自定义值 8000
provider = OpenAICompatibleLLM(settings, profile)
```

## 数据库结构

### 新增字段

```sql
ALTER TABLE user_model_settings ADD COLUMN max_output_tokens INTEGER;
```

- **类型**：INTEGER
- **可空**：是（NULL 表示使用全局配置）
- **范围**：1-32768（前端会验证）

### 查询示例

```sql
-- 查看用户的自定义配置
SELECT user_id, chat_model, max_output_tokens 
FROM user_model_settings 
WHERE enabled = 1;

-- 查看使用自定义 max_output_tokens 的用户
SELECT user_id, chat_model, max_output_tokens 
FROM user_model_settings 
WHERE max_output_tokens IS NOT NULL;
```

## API 变化

### GET /api/model-settings

**响应增加字段**：

```json
{
  "enabled": true,
  "base_url": "https://api.openai.com/v1",
  "chat_model": "gpt-4",
  "max_output_tokens": 8000,
  "default_max_output_tokens": 2048,
  ...
}
```

- `max_output_tokens`: 用户设置的值（null 表示未设置）
- `default_max_output_tokens`: 全局默认值

### PATCH /api/model-settings

**请求可包含**：

```json
{
  "max_output_tokens": 8000
}
```

- 留空：不修改
- 设置为具体值：使用该值
- ⚠️ 注意：不支持设置为 null 来清除，省略该字段即可

### 2. 智能推荐

根据用户填写的模型名称，自动推荐合适的值：

```javascript
const modelLimits = {
  'gpt-4': 8000,
  'gpt-3.5': 4000,
  'claude-3': 4000,
  'qwen-': 8000,
  'glm-4': 8000,
  'deepseek': 4000,
}

function suggestMaxTokens(modelName) {
  for (const [prefix, limit] of Object.entries(modelLimits)) {
    if (modelName.includes(prefix)) {
      return limit
    }
  }
  return null // 使用全局默认
}
```

## 常见问题

### Q1: 修改 max_output_tokens 后，旧的对话会受影响吗？

**答**：不会。只影响新发送的消息。历史对话使用的是当时的配置。

### Q2: 如果设置的值超过模型实际上限会怎样？

**答**：模型会使用自己的上限。例如设置 10000，但 GPT-4 上限是 8192，实际会用 8192。不会报错，但会在 `finish_reason` 中标记为 `length`。

### Q3: 可以为默认百炼配置单独设置吗？

**答**：不可以。默认百炼始终使用 `CHAT_MAX_OUTPUT_TOKENS` 全局配置。只有自定义模型支持独立配置。

### Q4: 输出 token 越大，费用越高吗？

**答**：是的。大多数模型按实际生成的 token 计费。设置上限不会增加费用，但允许模型生成更长的回答。

### Q5: 建议设置多大的值？

**答**：
- **简洁回答场景**：2048-4096
- **代码生成场景**：4096-8000
- **详细文档场景**：6000-8000
- **技术深度分析**：8000（接近上限）

## 性能影响

- **数据库**：增加一个可空整数字段，几乎无性能影响
- **查询**：不涉及索引，查询速度无变化
- **内存**：每个 ModelProfile 增加 8 字节（一个 int）

## 安全考虑

- ✅ **输入验证**：1-32768 范围限制
- ✅ **权限控制**：只能修改自己的配置
- ✅ **并发保护**：执行中的任务不能修改配置
- ✅ **向后兼容**：旧客户端忽略该字段，使用全局默认
