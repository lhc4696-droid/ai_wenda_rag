# 本地文件编程与项目授权

文件名沿用旧版以保留已有链接；2026-10-13 起授权单位为项目，一个项目下面支持多个独立对话。升级和验收见 [项目目录与多对话](项目目录与多对话.md)。

## 这次改成了什么

「编程工作台」现在操作用户在浏览器中选择的真实文件夹，不必先压缩上传，再下载覆盖。可以选择空目录新建项目，也可以读取现有源码后修改。**旧 ZIP 工作台及对应导入/下载 API 已下线，不再保留次要入口。** 原有项目快照和任务数据不删除，迁移 006 继续保留；聊天、附件和 RAG 不改动。

这是浏览器本地文件编程版本，不是已经具备终端、依赖安装、运行测试等能力的完整桌面 Agent。

完成回答下方由前端单独显示一次灰色能力说明，不再将固定“系统说明”拼入 AI 回答。旧记录末尾已有的一条或多条固定说明会在接口输出和组装模型历史时移除，不改写数据库原始记录；模型对具体文件未运行验证、操作失败等实际说明仍保留。

**聊天式界面已实现（2026-10-09 收尾）**：中间展示需求和 AI 回复，复用基础聊天的消息组件；左侧为项目目录，右侧为执行过程，底部为输入框。目录支持树形折叠与筛选，两侧可收起，窄屏按需展开；修改前后对照在点击后弹出，不常驻占据正文空间。

**现已接入项目和连续编程会话**：一个项目绑定一个目录，其下多个对话复用该目录，但聊天上下文各自独立。每次发送仍有独立的执行任务、授权令牌、停止控制与恢复备份；执行结束不结束会话，也不解除项目目录绑定。项目可自定义名称，留空按账号顺序编号；最新数据库版本为 11。

## 两层授权，不是绕过浏览器

1. 在底部输入编程需求，点击发送箭头或按 Enter；Shift + Enter 换行。未输入需求时发送按钮不可用，下方会显示原因。
2. 首次连接时，知言说明此项目下的所有对话将读写所选目录，并把必要源码片段发给后端和 AI 服务；也可先点击左侧添加项目或连接项目目录。
3. 确认连接，由浏览器显示目录选择及权限提示。
4. 选择具体项目目录并允许读写，知言才启动任务。拒绝或取消不启动模型任务。
5. 在同一个对话继续，或在同一项目新建对话：连接仍有效时直接使用原目录，不重新弹窗。每轮重新扫描路径、读取需要修改的文件，不复用上轮的文件读取基线。
6. 停止或超时只结束本轮执行，目录仍绑定项目；主动断开对整个项目生效，之后需明确重新连接。退出账号或登录失效时清除此账号保存的目录绑定，聊天记录不删除。

这是「一个项目、一个目录、多个独立对话」的持续授权，不是后台自动执行许可。只有你再次发送需求，才启动下一轮。目录句柄按账号和项目保存在本站浏览器的 IndexedDB，不上传后端；本轮工具令牌仍只保留在页面运行状态中。主动断开会禁用绑定，并保留原句柄仅供下次显式连接核对身份；删除项目或退出账号会清除相应句柄，删除单个对话则保留项目连接。

刷新或重新打开历史对话时，只查询浏览器是否仍授予读写权限；若仍有效，可继续使用记住的目录，**不会自动运行任何旧任务**。若权限已失效但保存的句柄仍在，提示「恢复访问」，用户点击后直接对原目录请求浏览器权限，不要求再选文件夹，也不静默申请。拒绝后不会启动任务或自动弹目录选择器；记录丢失时才要求选目录，句柄无法使用时可手动重新选择。浏览器不保证跨重启始终保留权限，依据：[Chrome 文件句柄与权限说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[MDN requestPermission](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemHandle/requestPermission)。

有原句柄时，重新连接使用 `isSameEntry` 核对实际目录，不能仅凭名称相同替换项目。换浏览器或退出后没有原句柄时，只能由用户明确选择原目录，不能声称已核对绝对路径。另一个目录应添加新项目，不要将旧项目上下文用于同名的其它目录。迁移 010 保留旧句柄键，不会把已断开的连接重新启用。

网页不能用自己的按钮替代浏览器的安全授权。`showDirectoryPicker` 需要用户点击、支持该能力的浏览器以及安全上下文。开发时使用桌面 Chrome / Edge 访问本机 `http://127.0.0.1:5173` 或 `http://localhost:5173`，正式部署使用 HTTPS；普通局域网 HTTP 地址通常不满足条件。页面会检测能力，不支持时禁止启动本地任务。依据：[MDN showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)、[Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。

## 谁负责读写

```text
首次批准项目会话，并通过浏览器选择文件夹
  → 在同一对话发送本轮需求，检查已有目录绑定和浏览器权限
  → 浏览器重新扫描允许访问的源码路径（不一次读取全部正文）
  → FastAPI 校验账号、会话归属和任务额度，加入本会话近期上下文
  → 模型提出读取 / 搜索 / 创建 / 精确修改工具请求
  → 当前浏览器核对任务、权限、路径和冲突后执行
  → 浏览器回传必要片段及执行结果
  → 模型继续规划，直到结束或达到限制
  → 本轮结束，保留对话和目录绑定，等待用户下一条需求
```

实际文件读写发生在用户浏览器，后端既不接收绝对路径，也不把用户路径交给 Python 的文件 API。服务器部署到云端后仍是同一原则，不会把服务器目录误当成用户电脑目录。

允许的工具：`list_files`、`read_file`、`search_code`、`write_file`（仅新建）、`replace_text`（先读取、唯一精确替换）。本模式没有删除工具，也不运行 shell、Python、npm、测试、Docker 或安装脚本。恢复操作中的删除只用于撤销本次新建且内容仍匹配的文件，由用户另行批准。

## 文件安全和恢复

- 只能使用所选目录下的相对路径，拒绝绝对路径、`..`、Windows 保留名等。
- 跳过 `.git`、`.ssh`、`.aws`、`venv`、`node_modules`、构建目录、`.env` 和常见凭据文件。不能识别普通源码里隐藏的全部秘密；不要授权包含敏感代码或数据的目录。
- 修改现有文件前须先读取。写入前会比较读取基线与当前内容；发现外部变化时不直接覆盖，需要重新读取。
- 每次落盘前，必须先把原始内容和待写入内容记录到浏览器 IndexedDB。存储失败则不允许继续写入。任务中断时会保留「需核对写入结果」的记录。
- 点击停止会关闭后续操作的权限入口，并尽力取消正在执行的操作；已经提交的写入不会自动撤销，极短的提交窗口仍可能完成。
- 「恢复修改前内容」需要再次批准并选择原目录。只恢复与本次记录匹配的文件，遇到后续修改则跳过；新建文件可以撤销，但不递归删除目录。
- 恢复时要求目录名称一致，并检查文件内容，但同名不等于同一个目录，请用户确认选的是原目录。
- 恢复记录仅保存在当前浏览器、当前站点；换浏览器、换域名/端口、清理站点数据后不能依靠它恢复。记录含源码原文，不加密；共享电脑上要谨慎处理。清除恢复记录不会删除磁盘项目。
- 同一站点的两个知言标签页使用 Web Locks 避免同时写入；它不锁住 VS Code、其他程序或其他站点。浏览器文件 API 没有提供本实现所需的跨进程原子比较并写入保证，内容复核是尽力的冲突保护，不是绝对防覆盖保证。重要项目务必使用 Git/备份，运行任务时避免其他程序同时编辑。

会话和任务历史保存在后端，目录绑定和恢复记录保存在浏览器，两者独立。删除后端会话不会删除本地项目或恢复备份；会移除此会话的浏览器目录绑定。刷新后只查看历史，不会继续执行遗留工具请求；若有未结束任务，先通过页面的未结束任务入口停止，再继续发送需求。仅查看其它标签页正在执行的历史，不会因离开查看页面而自动取消它。

右侧「执行过程」集中展示步骤、浏览器操作记录、本地修改和恢复记录。点击改动文件或正文中的修改卡片可打开前后对照；在「恢复记录」中点击「恢复修改」或「清除备份」仍需确认。顶部「目录」「过程」可展开或收起两侧，窄屏展开后可点击遮罩或按 Escape 收起。执行中，输入框旁和过程面板均保留停止入口。

## 当前限制

| 项目 | 限制 |
| --- | --- |
| 支持内容 | UTF-8 文本源码，例如 Python、Vue、JS/TS、HTML/CSS、Kotlin、Markdown；不是所有文件类型 |
| 可访问源码数量 | 150 个 |
| 单文件 | 128 KiB |
| 可访问文本总大小 | 2 MiB |
| 扫描保护 | 最多遍历 2500 个条目，限制递归深度；过大请选择子目录 |
| 一条用户需求内的模型工具循环 | 默认最多 12 轮，受 `CODING_MAX_STEPS` 控制；与对话消息轮数不同 |
| 单任务总时间 | 默认 300 秒，受 `CODING_TASK_TIMEOUT` 控制 |
| 本地恢复记录 | 每个站点内当前账号最多保留 10 份有修改的记录 |
| 编程会话 | 每个账号最多 100 个 |
| 服务端执行记录 | 每个会话最多 200 轮、每个账号最多 1000 轮；单任务列表接口返回最新 50 条，会话详情返回其完整轮次 |
| 模型会话记忆 | 最近最多 12 个已结束轮次的需求和结果，序列化历史正文预算约 18000 字符；不等于无限上下文 |

当前是小型项目起步版，目录过大时选择项目子目录，不要直接选择磁盘根目录、整个用户目录或含大量依赖的工作区。本地任务沿用编程任务每日配额和现有模型调用额度；停用旧工作台不重置历史用量，多轮任务不等于只调用一次 API。

## 配置和启动

不需要为本地读写安装桌面客户端，也不需要 Docker。继续使用 `DASHSCOPE_API_KEY`；`QWEN_CODING_MODEL` 留空时沿用 `QWEN_MODEL`，所选模型须支持 DashScope 文本 Function Calling。`CODING_SANDBOX_ENABLED` 是旧沙箱配置，本地模式不执行命令；修改该开关或构建旧镜像不会恢复已下线的 ZIP 工作台。

数据库结构升级到 **版本 8**。`008_local_coding_conversations.sql` 新增 `local_coding_conversations`，为任务增加 `conversation_id` 和 `turn_index`。每个旧本地任务迁为独立会话，保留指令、结果、步骤和任务编号；旧 ZIP 表与数据不删除。旧任务表在同一迁移事务中复制重建，以补齐非空字段和外键；不要删库重建。**本轮只编写迁移和用例，没有执行真实数据库迁移。** 后端启动会自动升级，因此建议先停止正在运行的后端，再在项目根目录备份并迁移：

```powershell
.\venv\Scripts\python.exe backend\migrate_db.py --backup
```

再按原方式启动后端和前端：

```powershell
.\venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload
```

另一个 PowerShell：

```powershell
cd frontend
pnpm dev
```

本实现仅支持单后端实例、单 Uvicorn worker。开发热重载会中断任务，不自动重放文件写入。上线需要 HTTPS、Cookie/来源保护、严格防 XSS、服务访问控制、配额与日志管理；不要直接暴露开发服务器。

## 数据库保存什么

`local_coding_projects` 保存项目和目录显示名，`local_coding_conversations` 保存所属用户、项目编号、标题、轮次数和时间；不保存浏览器文件句柄、用户绝对路径或服务器挂载目录。`local_coding_tasks` 保存会话编号、单调递增的对话轮序、任务指令、授权令牌摘要、模型轮次、待执行工具、步骤及结果。前端不提交任意历史给模型，后端按当前用户与当前会话读取历史。

后续请求只加入本会话近期轮次的需求与回复/错误说明，不重用旧工具调用或源码快照；提示词明确历史不是当前磁盘内容，修改前必须重新读取。源码片段和工具上下文在任务运行期间暂存 SQLite，正常结束、取消、过期清理或重启恢复时清空；需求、步骤及摘要仍保留供对话使用，可能含代码，WAL 与备份也可能保留旧数据。这不等于安全擦除，更不等于代码从未上传。

完整目录不会自动上传，但列出的相对路径、用户需求、模型读取/搜索命中的内容以及模型生成的代码会经过后端和模型提供方。真正的原文件和修改前恢复副本在用户设备。

## 主要文件和接口

- `frontend/src/components/LocalCodingWorkspace.vue`：聊天式三栏布局、授权框、任务循环、停止、进度、改动对照和恢复入口。
- `frontend/src/local-coding.css`：编程界面的三栏布局、窄屏侧栏、输入框和对照弹窗样式。
- `frontend/src/lib/coding-view.js`：仅根据已有路径元数据生成目录树，处理筛选与折叠，不读取磁盘，也不扩大文件访问范围。
- `frontend/src/lib/local-files.js`：浏览器路径校验、目录读写、冲突检查、IndexedDB 恢复记录。
- `frontend/src/lib/coding-bindings.js`：按账号与项目保存、检查、禁用和清除目录绑定，恢复时仅检查权限，不弹窗或自动执行。
- `frontend/src/App.vue`：账号退出、失效或切换时清理离开账号的目录绑定。
- `frontend/src/api/local-coding.js`：本地任务接口请求和离页取消。
- `backend/app/coding/local_routes.py`：受登录保护的本地能力、任务、轮次结果、停止和记录删除接口。
- `backend/app/coding/local_service.py`：本地编程提示词、允许工具、模型轮次调度；复用现有模型额度保护。
- `backend/app/coding/local_store.py`：账号隔离、任务状态、授权令牌摘要验证、幂等提交、过期/重启中断。
- `backend/app/coding/local_schemas.py`：任务与工具结果的数据格式。
- `backend/sql/migrations/007_local_coding.sql`：新增本地任务表。
- `backend/sql/migrations/008_local_coding_conversations.sql`：连续会话结构与旧任务保留迁移。
- `backend/sql/migrations/010_local_coding_projects.sql`：项目实体、会话所属项目和旧句柄兼容迁移。

`GET /api/coding/local/capabilities` 返回当前编程模型与轮次上限，需要登录；它替代已下线的 `GET /api/coding/capabilities`。

项目接口 `/api/coding/local/projects`：POST 创建、GET 列表；`/{id}` DELETE 删除项目及其对话记录，不删除用户文件。会话接口 `/api/coding/local/conversations`：POST 创建、GET 列表；`/{id}` GET 会话及其轮次、DELETE 删除会话。创建参数为 `client_conversation_id`、`project_id` 和 `directory_name`，所有接口检查登录和归属。

任务接口 `/api/coding/local/tasks`：POST 创建时必须带 `conversation_id`，并校验目录名与会话一致；GET 列表；`/{id}` GET 详情/DELETE 单轮记录；`/{id}/results` POST 交回本轮工具结果；`/{id}/cancel` POST 停止本轮。服务器的令牌校验防止错配任务，但不能替浏览器授予文件权限，也不能独立证明客户端真的执行了文件操作。旧 ZIP 接口仍不可用。

## 交给你验收

本轮仅静态检查，不运行模型、不修改用户目录、不跑功能测试。首次建议选择临时空目录或项目副本。

1. 拒绝知言授权、取消浏览器选目录：不得启动模型或改文件。
2. 首次连接空目录，要求创建一个简单页面：文件应直接出现在该目录。
3. 在同一个对话说「把刚才的按钮改成蓝色」：不再选目录，两轮消息均保留，AI 应先读取当前文件再修改。
4. 执行中停止后再发需求：仍用原目录；刷新、切回历史不得重放工具。刷新后权限有效则恢复连接，权限失效则明确提示重连。退出账号再登录应需要重新连接目录。
5. 模型读取后在编辑器修改同一文件：应报告冲突，不直接覆盖旧基线。
6. 执行结束后恢复：选择原目录，新建文件应删除、修改文件应还原；有后续修改的文件应跳过。
7. 不支持的浏览器、过大目录、过期登录、错误 Key、网络中断：应明确提示，已有改动可通过恢复记录核对。
8. 桌面上检查中间聊天、左侧目录、右侧过程能独立滚动；收起两侧后正文应扩展。缩窄窗口后检查侧栏按需展开、遮罩与 Escape 关闭正常。
9. 检查目录筛选与折叠、长文件名省略、修改对照弹窗；清除备份后当前修改列表应同步更新，但磁盘文件不变。
10. 两个项目各建多个对话并切换：消息和修改记录不得串用。同项目新对话应复用目录，不继承其他对话上下文；跨项目不得串用句柄。
11. 主动断开后不能再直接发起文件操作；有原句柄时选择另一个同名目录应被拒绝。在另一个标签断开后，正在运行的页面应在后续工具执行前发现绑定失效并停止。
12. 升级前备份，升级后检查旧任务仍在各自会话中；不能读删其它账号的会话。迁移失败时停止排查，不删除旧数据库。
