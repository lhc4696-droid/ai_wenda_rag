# 用户自定义模型配置

更新日期：2026-10-12

## 1. 这次支持什么

登录后进入右上角「账号设置 → 模型设置」，可以选择：

- **项目默认**：继续使用后端 `.env` 中配置的百炼模型。
- **我的 API**：当前账号使用自己的 API Key、Base URL 和模型名称，不影响其他账号。

自定义服务须兼容 **OpenAI Chat Completions** 协议。后端会向 `Base URL + /chat/completions` 发送请求，使用 Bearer API Key；仅填写其他平台原生 API 的地址并不保证兼容。接口采用非流式响应、`max_tokens` 输出限制，Coding Agent 还会发送 `tools`、`tool_choice` 和 `parallel_tool_calls: false`，需要平台和模型支持这些参数。

消息与工具调用格式依据 [OpenAI Docs：Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 核对；第三方服务的兼容程度仍应以该服务文档和实际验证为准。

| 功能 | 使用的配置 |
| --- | --- |
| 普通文字聊天 | 自定义聊天模型 |
| RAG 检索后生成答案 | 自定义聊天模型；检索到的必要片段会发送给该服务 |
| Coding Agent | 自定义 Coding 模型；留空时沿用聊天模型，必须支持工具调用 |
| 图片理解 | 可选的自定义视觉模型，沿用同一 Base URL 和 Key |
| RAG 文本向量生成 | 保持服务器原有 `EMBEDDING_MODEL` 和百炼 Key，不使用个人聊天模型 |

自定义视觉模型为空时，不会偷偷改用服务器的视觉模型：新图片上传会提示未配置，包含历史图片的请求也会明确报错。若聊天模型本身支持图片，可以在视觉模型一栏填写相同模型名称。

当前每个账号保存一套地址和 Key，不是多供应商配置列表；不支持本机 Ollama、内网地址、HTTP、Azure 专用鉴权或厂商独有接口。选择不同模型只改变模型服务，不会增加浏览器 Coding Agent 的文件权限，也不会启用终端执行。

## 2. 维护者先完成的配置

以下命令由你按需执行；本轮开发没有安装依赖、修改真实 `.env`、启动服务或迁移真实数据库。

在项目根目录更新后端依赖：

```powershell
.\venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

生成一次专门用于加密用户 API Key 的 Fernet 密钥：

```powershell
.\venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

将你终端中生成的完整字符串手动填入 `backend/.env`，不要发到聊天、截图或提交到仓库：

```dotenv
MODEL_CONFIG_SECRET=这里填写刚生成的Fernet密钥
```

这不是模型平台提供的 API Key，也不是 `EMAIL_CODE_SECRET`。它由项目维护者生成并保存在服务器上，所有账号的个人 Key 使用它加密。不要每次启动都生成新值；换机或部署时需要安全迁移同一个值，否则旧密文不能解密，只能让用户重新填写个人 Key。数据库备份与这个密钥都要保护，建议分开保存。

未配置、格式错误或缺少 `cryptography` 时，页面会提示安全存储尚未配置；默认模型仍可使用。已经启用的个人配置如果无法解密，会明确报错，不会擅自回退到项目默认服务。用户仍可关闭或删除该配置。

“我的 API”按钮不可选时，不代表后端没有重启，而是加密存储尚未就绪。完成配置并重启后，可点击「重新检查配置」更新状态，不必反复关闭网页；这个检查只读取配置状态，不调用模型、不产生模型费用。

停止后端、备份并升级数据库后再启动：

```powershell
.\venv\Scripts\python.exe backend\migrate_db.py --backup
.\venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload
```

数据库版本为 **9**，新增 `user_model_settings`，不会清空账号、聊天或编程历史。后端启动也会自动检查迁移版本，但升级前应先备份。不要删除数据库，也不要用新 `schema.sql` 直接替代旧库迁移。

## 3. 用户怎么填写

1. 打开右上角账号设置，选择「模型设置」。
2. 切换到「我的 API」。
3. 从服务商文档复制 **HTTPS 基础地址**。例如服务实际请求路径是 `https://api.example.com/v1/chat/completions`，则 Base URL 填 `https://api.example.com/v1`；这是格式示意，不是可用服务地址。部分平台基础地址带有 `/compatible-mode/v1` 等前缀，应完整保留。
4. 填写这个服务的 API Key、聊天模型 ID。模型 ID 须与该服务提供的名称完全一致。
5. 按需填写 Coding 模型、视觉模型；这两个模型必须能使用相同的地址和 Key。
6. 确认该平台可信，可先点击「测试聊天」或「测试 Coding」，再点击「保存并使用我的模型」。

保存只做格式和安全存储检查，**不会自动发送付费模型请求**；保存成功不代表地址、额度、权限和模型兼容性已验证。只有主动点击测试或发送实际消息时才请求模型。

已保存的 Key 不会回传到输入框，只显示「已保存密钥」。修改模型名称时可以留空保留 Key；**修改 Base URL 必须重新输入 Key**，避免把旧平台的密钥发到另一个地址。切回默认会保留个人配置，点击删除则移除配置并恢复默认。

切换模型后继续旧对话时，必要的旧对话内容也会发送给新服务。请注意聊天、附件和项目代码的保密要求。RAG 的文档切片仍会发给原有 Embedding 服务，并非所有资料都只经过个人模型服务。

聊天或编程任务正在运行时，修改/删除配置返回 `409`；请等任务完成，或先停止编程任务。这样不会在同一次多轮工具执行中途切换平台。设置生效后不需要重新创建普通聊天，也不需要重新选择已授权的项目目录。

### 测试连接

模型表单下方的测试区域使用**当前填写的内容**，可以在保存之前验证，不修改或启用数据库里的配置。

- **测试聊天**：发送固定的简短文字，检查服务能否返回有效回答，不只检查 HTTP 200。
- **测试 Coding**：向 Coding 模型发送一个无副作用的测试工具定义，检查是否返回符合格式的工具调用。Coding 模型留空时测试聊天模型。不会执行该工具，也不会访问用户文件夹。
- 每次点击最多发送一次模型请求，不自动重试。服务端模型等待上限为 20 秒（如果项目聊天超时更短，则沿用更短值），前端等待上限为 30 秒。
- 会显示本次测试的成功/失败、模型、耗时，以及可用的错误类别和排查编号。不回显 API Key、原始上游报文或模型回答正文。
- 测试仅发送固定提示，不携带聊天历史、附件、RAG 资料或项目代码。**可能产生少量个人模型服务费用，计入个人 API 调用统计，但不扣默认模型的每日额度；已受理的失败测试也计次，频率与并发限制保留。**
- Key 留空时，只能使用当前账号为同一个规范化地址保存的 Key；更换地址后必须重新输入。测试新 Key 不会把它保存到数据库，成功后仍需点击保存才能生效。
- 测试期间禁止重复点击和修改表单；完成后保留尚未保存的 Key，方便继续保存。修改表单内容后会清除旧测试结果，避免把旧配置的成功状态当成新配置已验证。
- 超时或浏览器断开不能保证服务商没有生成或计费；先确认网络和平台状态，不要连续重复点击。

一次成功仅证明当时的小型请求可用，不保证图片理解、大上下文、RAG Embedding 或完整多轮编程任务都能运行。这些能力仍需分别验收。

如果在接口文档里手动调用 `POST /api/model-settings/test`，请看响应的 `ok` 字段：`true` 才表示探测通过。HTTP 200 也可能伴随 `ok: false`，表示测试流程完成，但模型调用失败或响应不兼容；页面会据此显示“测试未通过”。配置格式错误和项目限流仍使用 4xx 状态码。

### Clash Verge / TUN / Fake-IP 代理

遇到“模型地址解析到了禁止访问的网络”，不一定是 API Key 有误。开启 Fake-IP 时，可由部署者在后端配置 `CUSTOM_MODEL_PROXY_URL` 和 `CUSTOM_MODEL_PROXY_BASE_URLS`，为精确匹配的可信基础地址启用本机 HTTP/Mixed 代理。个人模型页面仍填写平台 Base URL，不填写代理端口。

配置方法、Clash Verge 端口确认、错误分类与上线边界见 [Clash Verge 与自定义模型代理配置](Clash-Verge与自定义模型代理配置.md)。默认留空不改变现有行为；本次没有改写真实 `.env`。仅配置代理功能不需要数据库迁移或新增依赖。

## 4. 安全与部署边界

- Key 通过 HTTPS 站点提交给后端，后端需要在调用时解密；不是仅保存在用户电脑的端到端秘密。生产环境必须部署站点 HTTPS。
- SQLite 只保存 Fernet 密文；载荷绑定用户 ID 和规范化后的 Base URL，其他账号或被篡改的地址不能复用原密文。
- 配置接口需要登录并检查请求来源，不接受用户指定其他账号 ID；所有响应设为 `no-store`，不返回 Key。
- 前端不把个人 Key 写入 localStorage、sessionStorage 或 IndexedDB，保存结束、切换设置板块或关闭后清空输入。
- 个人 Base URL 仅支持公网格式 HTTPS，拒绝本机和内网字面地址。默认直连时，在连接解析器中检查 DNS 返回的全部 IP，拒绝私网、回环、链路本地和保留地址等。
- 部署者显式配置本机代理并精确匹配可信 Base URL 时，由代理负责目标 DNS 与出站限制；不是对任意目标放行，也不能声称应用仍校验了代理最终连接的公网 IP。公开部署需配套出口访问控制。两种模式均不继承环境代理、不跟随重定向，保留 TLS 验证。
- 服务端限制超时与请求/响应体大小，不将上游错误正文、请求头或密钥写入错误提示。
- 自定义服务仍受项目的账号调用次数、并发、上下文和工具权限限制。平台实际账单由个人 Key 所属账号承担；项目调用统计不是计费账单。
- 删除配置不等于安全擦除历史 WAL、旧备份或服务商日志；泄露时应同时到服务商撤销旧 Key。

这些约束不是上线前的完整安全审计。正式部署还应配置出站网络限制、访问日志脱敏、反向代理 HTTPS 和备份恢复。

## 6. 留给你执行的验收

- 未登录无法读取、保存或删除配置；两个账号互不影响。
- 默认模型仍正常；启用个人配置后，聊天与 Coding 使用个人模型，Embedding 名称和向量库不变。
- 刷新页面后仍保留选择，只显示 Key 已保存，不返回明文。
- 换模型名称可保留 Key，换地址必须重新填 Key；无效 Key、错误模型、限流和不兼容接口均显示明确错误。
- Coding 连续会话仍能复用目录，配置不能在运行中途改变。
- 图片配置为空时明确提示；配置支持图片的视觉模型后才启用图片能力。
- 关闭个人配置恢复默认；删除个人配置后重新启用必须重新填写 Key。
- 旧数据库升级到 9 后，原账号、普通聊天和编程历史保留。
- 未保存的配置可以测试；成功不会自动启用，失败不会覆盖原配置。
- 聊天测试成功但 Coding 测试失败时，分别核对工具调用能力；测试不产生会话记录或文件修改。
- 修改地址但不重新填写 Key 时，不会向新地址发送原 Key；限流、无效回复和超时明确显示失败。

## 调用额度（2026-10-22 更新）

个人 API 的聊天、流式、编程和连接测试均不扣默认模型日额度。服务器 Embedding 独立限额，调用来源分别统计；详细规则及版本 13 迁移见 [个人 API 与模型调用额度](个人API与模型调用额度.md)。
