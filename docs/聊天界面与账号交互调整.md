# 聊天界面与账号交互调整

日期：2026-09-17。

## 本轮变化

- 聊天标题相对主聊天区域居中；模型信息在左，账号在右。长标题省略显示，鼠标悬停可查看全文。小屏保留居中标题和账号头像。
- 切换会话保持输入框与消息区域布局稳定，消息使用短淡出、淡入；加载时显示低对比度的消息骨架，快速请求不强制等待。
- 打开历史直接定位到最新消息，不从顶部缓慢滚动；阅读旧消息时，回答到达不会强制拉到底部。切换历史不自动聚焦输入框，避免触屏弹出键盘。
- 桌面侧栏改名、删除按钮在悬停、键盘聚焦或选中时突出显示；触屏保留可见按钮。遵循系统“减少动态效果”设置。
- 右上角菜单统一为“账号设置”和“退出登录”。设置内仍有“账号资料”“安全设置”，修改密码功能没有删除，只移除重复快捷入口。
- 修改用户名不再要求当前密码；真正修改密码仍验证当前密码、确认新密码。成功后撤销旧登录，并给当前浏览器换发凭证，显示成功提示、清空密码输入框，保留聊天与草稿。邮箱找回密码仍要求全部重新登录。

## 后端契约

`POST /api/auth/username` 请求现在仅为：

```json
{"username": "new_name"}
```

登录校验、可信来源检查、字段限制、重名检查、修改频率限制，以及写入事务内的会话与版本复核保持不变。用户名是登录标识，不是昵称，修改后应使用新用户名登录。不要在共享设备上留下有效登录会话。

无需数据库迁移、额外依赖或修改 `.env`。请重启后端并刷新前端；旧前端继续发送 `current_password` 会因多余字段被接口拒绝。

## 主动改密的登录保留

后端在一个事务中修改密码、撤销旧会话、创建新的当前会话并作废旧邮箱验证码。新令牌只通过 HttpOnly Cookie 返回，不写入响应正文；若新会话写入失败，密码修改与撤销操作同时回滚。

前端不再销毁聊天页面。同一浏览器的标签页共享 Cookie，收到 `session-rotated` 通知后刷新账号状态、不主动清空聊天；其他浏览器或设备在下一次受保护请求时发现旧登录失效，不依赖实时推送。

如果改密事务已提交但网络中断，浏览器可能没有收到新 Cookie，此时需用新密码重新登录；前端不会自动重复改密。此改动无需数据库迁移或 `.env` 更新，重启后端并刷新前端即可。相关回归用例已同步，未运行功能测试。
