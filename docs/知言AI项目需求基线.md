### 3.1 沿用的输入和会话规则

- 用户名为 3–32 个英文字母、数字或下划线，不区分英文字母大小写。
- 密码为 8–128 个字符，不能全部为空格；错误反馈不回显密码。
- 聊天每条消息最多 20,000 个字符；新会话接口只接受当前问题、请求编号等控制字段及可选附件 ID，由后端读取历史与附件正文。
- 每条问题最多 3 个附件、单个默认 10 MiB；文档最多 16000 字符，PDF 最多 40 页。文档与图片预算共同计入上下文，最新问题超预算时拒绝并说明，不悄悄截断附件冒充全文。
- 取消一场会话最多 25 次提问的页面限制；完整历史持续保存，模型上下文最多选择最近 25 个成功轮次，再按字符预算裁剪。
- 当前前端等待上限为 120 秒。到达上限后结束界面等待并允许手动重试，不自动无限重试。
- 后端模型请求默认上限 90 秒；上下文含系统提示默认最多 40,000 字符，超限保留最近轮次；回答最多 20,000 字符，发生截断时提示。
- 默认每用户每分钟 10 次、每日 100 次，全站每日 1,000 次；同一用户并发 1、全站并发 4，可在后端配置。受理后失败也计数，每日额度在 UTC 零点（北京时间 08:00）重置。
- 新建对话或取消浏览器等待，不保证模型供应商已停止生成或计费；再次请求可能产生新的调用费用。
- 登录默认有效期为 7 天，可由后端配置调整。

上述条数和字数限制是应用输入边界，不等于任意模型都能接受同等大小的上下文。模型的上下文限制仍可能导致请求失败，需正常显示错误。

### 3.2 聊天记录的明确边界

- 会话与消息保存在 SQLite，前端不把聊天正文或登录凭据写入 localStorage。
- 刷新时恢复地址栏指定的会话；没有指定时打开最近会话。关闭页面、退出或改密不删除已保存历史。
- 新建对话不删除旧会话；点击新建时不立即生成空数据库记录，首条发送时创建。
- 会话每页 20 条，消息默认最近 50 条，支持读取更早数据。标题可由首问题前 30 字生成，也可手动修改至最多 80 字。
- 删除需要确认；成功后永久删除目标会话及其消息，无法恢复。正在回答的会话暂不能删除。
- 旧版未持久化且已经丢失的聊天无法补回；历史持久化不等于模型每次读取全部历史。

## 4. 核心使用流程

1. 用户打开页面，系统检查是否已有有效登录状态。
2. 未登录用户可登录，或先申请邮箱验证码再注册；忘记密码使用已验证邮箱重置。已登录用户进入聊天页面。
3. 用户输入问题，可选择上传附件；附件先在后端完成格式核验和本地解析，失败时明确提示，不允许带失败附件发送。
4. 前端提交会话 ID、当前问题、客户端消息编号、所见的最后消息序号及附件 ID，不提交文件路径或伪造历史。
5. 后端核对身份、来源、会话所有权、附件归属与序号，在同一事务保存待处理问题并绑定附件；读取成功历史，检查额度和并发并按预算组合上下文。
6. 模型调用模块通过 DashScope SDK 请求千问：仅文字/文档使用 QWEN_MODEL，上下文有图片时使用 QWEN_VISION_MODEL。
7. 成功时后端保存回答并完成用户消息，再返回前端；失败保留问题并标记失败，允许手动重试。
8. 用户可继续追问、新建、切换、重命名或删除会话，也可打开账号设置或退出登录。

用户提交的问题及本次选中的聊天上下文、文档正文和图片会发送给阿里云模型服务处理；仅上传和本地解析阶段不调用模型。本项目不是完全离线的本地模型，账号密码和登录令牌不得作为聊天上下文发送给模型。

## 5. 后端接口约定

沿用现有接口，不为第一阶段另建并行接口体系。

| 方法与路径 | 用途 | 正常结果 |
| --- | --- | --- |
| GET /api/health | 检查后端接口是否可访问，不验证模型密钥 | 200，status 为 ok |
| POST /api/auth/email-code | 申请验证码，字段 email、purpose（register 或 reset_password） | 202，统一受理提示和等待时间；不保证投递成功 |
| POST /api/auth/register | 注册并建立登录会话 | 201，返回用户信息并设置 Cookie |
| POST /api/auth/password/reset | 使用 email、code、new_password 重置密码 | 200，撤销该账号全部旧会话，不自动登录 |
| POST /api/auth/login | 验证账号并建立登录会话 | 200，返回用户信息并设置 Cookie |
| GET /api/auth/me | 查询当前登录用户 | 200，返回用户信息 |
| POST /api/auth/logout | 撤销当前登录会话 | 204 |
| POST /api/auth/username | 已登录用户仅提交 username 修改自己的登录用户名，无需再次输入密码 | 200，返回更新后的用户信息，保留登录 |
| POST /api/auth/password/change | 核对当前密码后设置新密码 | 200，原子撤销旧会话并创建当前浏览器新会话，通过 HttpOnly Cookie 换发凭证 |
| POST /api/chat | 旧临时聊天兼容接口，已弃用，不保存历史 | 200，返回 role、content、model 及裁剪提示 |
| GET /api/chat/usage | 查询自己的当日模型调用统计 | 200，返回次数、已知 Token 用量、额度及重置时间 |
| POST /api/conversations | 新建会话，同一 UUID 可重试 | 201，返回会话 |
| GET /api/conversations | 分页读取自己的会话列表 | 200，items、next_cursor |
| GET /api/conversations/{id}/messages | 读取消息，before 向前翻页 | 200，conversation、messages、next_before |
| PATCH /api/conversations/{id} | 修改 title | 200，返回会话 |
| DELETE /api/conversations/{id} | 删除会话及消息 | 204 |
| POST /api/conversations/{id}/messages | content、client_message_id、expected_last_sequence、retry、attachment_ids | 200，conversation、user_message、assistant_message、replayed，消息含附件元数据 |
| GET /api/attachments/capabilities | 查询允许的附件类型、大小及视觉模型是否配置 | 200，extensions、max_files、max_bytes、images_enabled、vision_model |
| POST /api/attachments | multipart/form-data，单个 file | 201，附件 ID、状态和安全元数据；解析失败时 status=failed，不代表可以发送 |
| GET /api/attachments/{id} | 查询自己的附件信息 | 200，不包含正文、磁盘路径或所有者 ID |
| GET /api/attachments/{id}/content | 查看自己的图片预览或下载文档 | 200，私有响应，不缓存 |
| DELETE /api/attachments/{id} | 删除自己的未发送附件 | 204；已绑定附件返回 409，随会话清理 |

新聊天接口不接受客户端伪造 messages 历史或 assistant 角色，只接收当前问题。系统提示由后端设置，历史从数据库读取。同一会话只有一个待处理问题；重复已完成编号返回原结果，响应丢失后前端先查询保存状态。会话不存在或不属于当前账号统一返回 404；序号过期、问题仍处理中等状态冲突返回 409。

错误处理约定：未登录或登录失败使用 401；账号设置中当前密码错误使用 400，不直接退出登录；不可信请求来源使用 403；重复用户名使用 409；输入校验失败使用 422；账号或模型请求超过限制使用 429，携带 Retry-After；模型超时使用 504，其余模型服务不可用使用 503。前端应解释错误，不把这些错误渲染成正常 AI 答案，也不泄露密钥、密码或内部堆栈。返回 X-Request-ID 便于定位日志，已分类错误提供 X-Error-Code。

## 6. 数据库范围与脚本

默认数据库文件为 backend/data/zhiyan.sqlite3，当前结构版本为 4，共十张表（原八张表加附件及消息关联）：

| 表名 | 保存内容 | 业务用途 |
| --- | --- | --- |
| users | 用户 ID、用户名、密码哈希、创建时间、邮箱、验证时间、认证版本 | 保存账号；邮箱唯一；保留无邮箱旧账号 |
| sessions | 登录令牌摘要、用户 ID、过期时间 | 检查登录、支持过期和退出；不是 AI 聊天记录 |
| auth_attempts | 请求计数及重置时间 | 注册、登录、发码和核验限流 |
| email_verifications | 邮箱、用途、用户 ID、HMAC 摘要、有效期、次数及状态 | 验证码核验、防重用和投递状态 |
| schema_migrations | 版本、应用时间 | 记录事务迁移，不以删库方式升级 |
| model_calls | 请求编号、用户 ID、模型、时间、状态、字符数、已知 Token 数、错误类别 | 调用额度、并发租约及统计；不保存问题和回答正文 |
| conversations | 会话 ID、用户 ID、标题、创建与更新时间、最后序号 | 账号隔离的会话列表 |
| messages | 会话 ID、客户端消息编号、顺序、角色、正文、状态、模型、错误与裁剪标志 | 保存问题和回答，支持幂等重试与异常恢复 |
| attachments | 所有者、所属会话、文件信息、解析正文、处理状态、额度及过期时间 | 私有文件的权限、解析结果及回收管理 |
| message_attachments | 消息 ID、附件 ID、顺序 | 关联历史附件，同会话修改失败问题时可复用 |

数据库相关文件职责：

- backend/sql/schema.sql：建表、约束和索引定义。
- backend/init_db.py：手动执行初始化的入口。
- backend/app/auth/store.py：初始化及日常数据库读写。
- backend/app/migrations.py、backend/sql/migrations/001_email_verification.sql、002_model_calls.sql、003_conversation_history.sql、004_attachments.sql：按版本升级与记录。
- backend/app/attachments/store.py：附件权限、配额和消息关联；storage.py 管理私有文件，service.py 管理解析流程和清理。
- backend/app/conversations/store.py：会话与消息读写、所有权检查、事务与幂等。
- backend/app/chat/store.py：模型调用配额、并发租约及元数据访问。
- backend/migrate_db.py：手动升级，支持 --backup 创建在线备份。
- backend/sql/README.md：数据库结构、初始化与备份说明。

启动时自动初始化；重复初始化不得清空已有账号。未来修改已有表结构时编写迁移脚本，不能把重复执行 CREATE TABLE IF NOT EXISTS 当作结构迁移。

第一阶段已增加会话、消息、附件及消息附件关联表，不增加知识库文档库、向量存储、课程表、工单表或 Agent 任务表，也不为使用更多技术而更换数据库。附件目录与数据库需一起备份；原有 --backup 只备份 SQLite。

## 7. 第一阶段品质要求

- 交互：提供等待、空状态、错误和输入限制反馈；核心操作可用键盘完成；保持现有桌面和手机适配。
- 安全：登录认证由后端执行；采用 HttpOnly Cookie；密码、原始登录令牌和真实 API Key 不写入前端持久存储或普通日志。
- 请求控制：保留请求来源检查和账号限流，增加模型请求额度与并发限制；超时后界面可以恢复操作；没有已确认的重试策略时不自动重试模型调用。
- 维护：页面、HTTP 请求、接口校验、认证、数据库访问和模型调用各自分开，避免全部写在单个文件中。
- 测试：自动化测试默认使用模拟模型和临时数据库，不消耗真实模型额度，不污染已有账号。
- 可交付：依赖和启动步骤清楚，真实 .env 与数据库文件不进入版本控制；保留示例配置和 SQL 脚本。
- 真实性：界面说明回答由 AI 生成、可能有误；未实现检索时不展示伪造的文件引用或“已联网”等状态。

本阶段以本地运行作为验收环境，不承诺生产级高并发、固定回答准确率或模型响应时长。公开部署涉及 HTTPS、Cookie 安全配置、调用配额等额外检查，另行确认范围。

## 8. 本阶段明确不做的功能

- Agent、工具调用、自主任务规划、后台持续任务。
- 企业知识库、RAG、向量检索、扫描件 OCR、复杂图表解析和独立来源卡片；短文档与静态图片上传已在 V1.4 纳入。
- 联网搜索、网页抓取、任意本地文件读取、代码或命令执行。
- 跨会话自动记忆、自动摘要、聊天搜索、批量导出与回收站。
- 流式输出、语音、生成文件导出和多模型切换界面；图片理解通过配置的视觉模型实现。
- 课程空间、练习出题、错因诊断、学习报告。
- 企业部门管理、多租户、复杂角色权限、管理员控制台。
- 模型训练或微调、多 Agent、可视化工作流平台。
- 除账号验证码和安全通知外的邮件发送、工单创建、其他数据库业务修改等外部或新增业务操作。
- 数据库替换、微服务拆分、容器集群和生产部署工程。

这些内容并非永久排除，而是不得在未调整需求范围的情况下加入当前版本。

## 10. 第二阶段：Agent 改造方向

本节只确定方向，不是当前版本的实现任务，也不表示已经确定具体工具清单。

### 10.1 常规单 Agent 的定义

1. 用户提出一个任务。
2. 后端把任务上下文和允许使用的工具说明提供给支持工具调用的模型。
3. 模型直接回答，或请求调用某个工具。
4. 后端检查工具是否开放、参数是否合法、当前用户是否有权限；需要确认的操作先等待用户确认。
5. 后端执行工具，将实际执行结果回传模型。
6. 模型根据结果继续选择下一步，或完成任务；达到步数、超时或费用限制时停止。

Agent 可以只做查询和分析，不要求必须写入数据。检索文件只是可选工具之一，不是 Agent 的全部含义，也不是第一阶段必须完成的前置功能。

### 10.2 改造时复用和扩展的内容

- 复用 Vue 页面基础、账号认证、FastAPI 接口结构、配置管理和数据库访问基础。
- 扩展模型适配层：现有“返回一段文字”的接口不能完整表达工具调用，需要增加工具请求与结果等结构。
- 增加任务协调与工具执行模块；具体业务操作保持独立，以便页面和 Agent 复用。
- 按实际需求增加任务记录、工具记录和页面执行状态，不在当前阶段提前建立空模块或所有未来数据表。
- 工具身份和权限来自后端认证，不能由模型自行声明；不允许任意函数名、任意命令或不受约束的数据库执行。
- 修改、删除、发送等操作按风险设置人工确认、防重复执行和审计记录。
- 展示可核实的工具名称、状态和执行结果，不伪装模型内部思考过程。
- 知识库内容和工具输出属于数据，不能作为绕过用户权限或系统规则的指令。

模型及 SDK 是否支持所需工具协议，在该阶段验证。换模型名不等于完成 Agent 改造；这里约定的是模块可扩展，不承诺未来零修改。

### 10.3 启动第二阶段前必须补充的需求

- Agent 具体帮助用户完成什么任务，以及该任务的完成标准。
- 开放哪些工具、使用哪些数据源，是否接入文件检索或联网搜索。
- 是否需要保存聊天历史、任务进度和工具执行记录。
- 哪些操作只读、哪些需要确认，以及失败恢复和防重复执行规则。
- 工具执行次数、耗时、模型费用等限制。
- 是否需要流式显示、后台运行或公开部署。

这些选择未确定前，不默认采用特定业务场景、Agent 框架、数据库或外部平台。

## 11. 实施与学习方式

1. 以本文检查已有功能与验收要求的差距，不推倒现有前后端重写。
2. 每次只处理一个明确模块或问题，先说明它的职责、接口与数据变化。
3. 实施后准备与风险相符的测试和操作步骤；用户明确要求自行测试时，只做约定的静态检查，并如实区分“代码完成”和“功能已验收”。
4. 用简单语言解释修改了哪些文件、为什么修改，以及请求如何在前后端间流转。
5. 第一阶段验收完成后，再补充第二阶段工具和任务需求，开始 Agent 改造。

新增需求应标明所属阶段、涉及页面或接口、数据变化及验收方式。未经明确纳入的讨论建议，不作为后续自动实施的依据。
