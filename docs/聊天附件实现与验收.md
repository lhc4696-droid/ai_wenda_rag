# 聊天附件实现与验收

日期：2026-09-21。API 版本 0.6.0，数据库结构版本 4。

## 本版范围

当前会话可上传 JPG/JPEG、PNG、静态 WebP、TXT、Markdown、文字型 PDF 和 DOCX，并附一句问题发送。文档提取正文后使用 QWEN_MODEL；上下文包含图片时使用 QWEN_VISION_MODEL。这不是知识库或 RAG，不建立向量索引，也没有新增多平台/多模型选择页面。

图片缩略图可以点击放大，文档可以下载。附件卡片显示上传解析中、就绪或失败状态。历史消息返回附件信息，刷新后仍能查看；失败问题重试复用附件编号，修改后重新提问允许在同一会话复用原附件。切换会话清空未发送附件，避免串入其他会话。

## 配置与启动

保留现有 `backend/.env`，不要用模板覆盖真实密钥。补充一个你在百炼账号所在地域有权限调用的视觉模型 ID：

```dotenv
# 普通文字和文档继续使用原来的 QWEN_MODEL
QWEN_VISION_MODEL=你在百炼控制台确认可用的视觉模型ID
ATTACHMENT_MAX_BYTES=10485760
ATTACHMENT_USER_QUOTA=209715200
```

例如可在平台确认 `qwen-vl-plus` 是否对你的账号可用后填写。留空时禁用图片上传，但文档和纯文字聊天正常可用；填写名称只代表启用配置，不保证上游权限、余额或模型能力。图片采用 DashScope 的异步多模态接口与 Base64 图片输入，参见[百炼视觉理解文档](https://help.aliyun.com/zh/model-studio/vision)和[多轮对话文档](https://help.aliyun.com/zh/model-studio/multi-round-conversation)。

升级前停止旧后端，项目根目录执行：

```powershell
.\venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\venv\Scripts\python.exe backend\migrate_db.py --backup
.\venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload
```

另一窗口进入 frontend 后执行 `pnpm dev`。没有新增前端依赖，不需要重建 venv。后端依赖新增 python-multipart、Pillow、pypdf 和 defusedxml，已安装到本项目 venv。正式构建未执行。

## 限制与准确性

- 每条问题最多 3 个附件；单个文件默认最多 10 MiB，可配置降低；每用户默认约 200 MiB 存储额度。每次上传先预留单文件上限加 3 MiB，完成后改计实际磁盘占用；账号额度至少要容纳这一次预留，否则启动时提示配置错误。
- 文档最多 16000 字符，PDF 最多 40 页；超限拒绝并要求拆分，不静默只读取前半部分。PDF 无文字页明确标注；纯扫描件、加密 PDF 不支持。
- DOCX 只读正文段落及其中的表格文字，不还原复杂表格关系，不读取页眉、页脚、批注、公式和嵌入图片。扩展名不代表内容一定有效。
- 图片最多 1600 万像素，重编码为不含 EXIF/GPS 的 JPEG 预览，最长边 2048 像素；不支持动图。预览和模型使用处理后的副本。
- 同一轮实际上下文最多含 3 张图片。仍只选择最近 25 个成功轮次，并按字符和图片的保守预算裁剪，文档正文计入预算。历史附件可能随旧轮次一起被裁剪；页面会提示上下文裁剪，不代表模型永久记得文件。
- 图片预算不是精确视觉 Token 计费；以平台返回的 usage 和账单为准。文档解析或上传成功也不代表模型已经分析它。
- 每进程最多并行 2 个解析流程，独立子进程解析超过 30 秒会结束并提示。上传处理失败时可以移除后重试。

## 存储与权限

仍使用 SQLite。新增 `attachments` 保存用户、文件信息、处理状态、提取正文及所属会话；`message_attachments` 记录消息与附件的关联及顺序。这样同一会话编辑失败问题时可复用文件，不必复制文件；跨会话引用被拒绝。

文件位于数据库同目录的 `attachments` 私有文件夹，默认 `backend/data/attachments`，不挂载为公开静态资源。实际路径只由后端随机 ID 构成，不使用用户提供的文件名。预览、下载、绑定及删除都检查当前登录身份，上传时用户 ID 从 Cookie 对应的服务端会话取得。

未发送附件保留最多 24 小时；失败/中断上传也会回收。删除会话时，数据库触发器将其附件标记为不可访问，后台每 60 秒尝试删除磁盘文件，失败后重试。已发送附件不能单独通过待发送附件删除接口移除。正常停止服务期间不清理，下一次启动后继续处理。

原文件、图片副本与提取正文属于私人数据，不应提交 Git。删除操作不可从应用中撤销；已有备份不会同步删除，需要自行管理。数据库与附件目录要一起备份，原来的 `migrate_db.py --backup` 只备份数据库，不能替代附件备份。

模型只会在发送问题时收到选中的正文/图片；上传和本地解析不调用模型。请求和错误日志不记录正文、图片 Base64 或密钥。图片/文件内的指令被视为资料而非授权；提示词约束不能保证完全消除提示注入，未来 Agent 必须另做工具权限检查。

这是一版本地项目实现，不是恶意文件的完整隔离沙箱。公开部署前还需要反向代理的请求大小/连接/速率限制、全站存储限额、恶意文件扫描和容器级解析内存/CPU 限制；解析子进程的超时不能替代硬性内存隔离。

## 接口与文件职责

| 接口 | 用途 |
| --- | --- |
| GET /api/attachments/capabilities | 类型、单文件大小、图片是否启用及视觉模型名 |
| POST /api/attachments | multipart/form-data，单个 file 字段；返回附件状态与编号，失败解析返回 status=failed |
| GET /api/attachments/{id} | 查询当前用户的附件信息，不返回正文或磁盘路径 |
| GET /api/attachments/{id}/content | 经身份校验的图片预览或文档下载，禁止缓存 |
| DELETE /api/attachments/{id} | 删除未绑定附件；已绑定返回 409 |
| POST /api/conversations/{id}/messages | 原字段基础上增加 attachment_ids，最多 3 个 UUID |

后端 `app/attachments/` 下：routes 是接口，schemas 是校验和安全返回结构，store 是权限/关联/配额，storage 是私有文件路径，service 是上传/子进程/清理，parsers 是文件解码，context 是模型输入组装。SQL 为 `sql/migrations/004_attachments.sql`。

前端新增 AttachmentPicker、AttachmentCard、AttachmentPreview、api/attachments.js 和 attachments.css；现有 useConversations 负责草稿附件、发送恢复和会话切换，ChatMessage 展示已保存附件。没有改写本轮开始前已有的 Markdown/公式渲染及其依赖变更。

## 验收清单

本轮仅做静态检查，未执行功能测试、真实模型/邮件调用、浏览器验收或实际数据库迁移。以下由使用者验证：

1. 上传短 TXT 或文字 PDF，等待就绪后提问；回答引用附件内容；继续追问可使用仍在上下文内的正文。
2. 配好视觉模型后上传静态图片，检查预览、回答及显示的模型名；取消配置时图片按钮提示能力未启用。
3. 刷新、退出再登录，历史附件仍在；另一账号不能用附件编号读取、下载或绑定。
4. 上传扫描 PDF、超长文件、伪装扩展名、空文件和超大文件，获得明确错误；解析失败不允许发送。
5. 上传过程中切换会话，迟到结果不进入新会话；发送失败后重试不重复绑定附件；修改失败问题可在同一会话复用附件。
6. 删除会话后附件立即不可访问，后台清理磁盘文件；未发送文件过期后回收。
