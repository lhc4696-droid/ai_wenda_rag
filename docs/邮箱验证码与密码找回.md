# 知言 AI：邮箱验证码注册与忘记密码

## 1. 已实现的功能与边界

- 新用户通过用户名、密码、邮箱和邮箱验证码注册；成功后自动登录。
- 登录仍然使用用户名和密码，不要求每次输入验证码。
- 注册、登录和重置密码统一接受 8–128 个字符，不能全部为空格；原有长密码仍可使用，无需修改数据库。
- 忘记密码通过注册时验证过的邮箱申请重置验证码，设置新密码后撤销该账号所有旧登录，不自动登录。
- 两种验证码按邮箱和用途隔离，不能混用；只可使用一次，重发后旧码失效。
- 旧账号和数据库保留。原来没有邮箱的账号不会被自动绑定或伪装为已验证；可以继续登录，但暂不支持邮箱找回。邮箱绑定/更换需单独实现带当前密码核验的流程。
- 本次没有实现历史记录、管理员或 Agent。

## 2. 配置真实邮件

在 [后端 .env](D:/code/project_python/wen_da/backend/.env) 中补充配置，不覆盖原有千问 API Key。可对照 [.env.example](D:/code/project_python/wen_da/backend/.env.example)。

| 配置 | 说明 |
| --- | --- |
| SMTP_HOST | 邮件服务商提供的 SMTP 服务器地址 |
| SMTP_PORT | 按服务商说明填写，隐式 TLS 常用 465，STARTTLS 常用 587 |
| SMTP_USERNAME | 发件账号 |
| SMTP_PASSWORD | SMTP 授权码或服务凭据，不是知言账号密码 |
| SMTP_FROM | 经服务商允许的发件邮箱 |
| SMTP_SECURITY | ssl 或 starttls，不支持明文连接 |
| SMTP_TIMEOUT | 单次 SMTP 网络操作超时，默认 10 秒 |
| EMAIL_CODE_SECRET | 至少 32 字符的独立随机服务器密钥，用于验证码 HMAC |
| EMAIL_CODE_TTL | 有效期，默认 300 秒；可配置 60–1800 秒 |
| EMAIL_CODE_COOLDOWN | 同邮箱同用途重发间隔，默认 60 秒；至少 30 秒且不超过有效期 |
| EMAIL_CODE_MAX_ATTEMPTS | 每个验证码最多核对次数，默认 5 次，可配置 1–10 次 |

在本地 PowerShell 生成摘要密钥，再把输出填入 .env（不要贴到聊天里）：

```powershell
.\venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
```

这个密钥应保持稳定并妥善保管。更换会使旧验证码无法核验，不会更改用户密码。真实 SMTP 凭据、验证码和摘要密钥不提交版本控制、不放进 Vue 代码、不写入普通日志。

缺少配置时申请验证码返回明确的 503；旧账号登录、健康检查和已有聊天不依赖邮件配置。发件账号还需要在所选服务商启用 SMTP/授权码，完成其要求的发件认证或域名配置。

## 4. 接口与实际操作

| 接口 | 请求字段 | 结果 |
| --- | --- | --- |
| POST /api/auth/email-code | email、purpose=register | 202 受理注册验证码申请 |
| POST /api/auth/register | username、password、email、code | 201 创建已验证邮箱账号并登录 |
| POST /api/auth/email-code | email、purpose=reset_password | 202 受理密码重置验证码申请 |
| POST /api/auth/password/reset | email、code、new_password | 200 改密，撤销所有旧会话，返回登录提示 |
| POST /api/auth/login | username、password | 200 普通登录 |

验证码为 6 位数字字符串，需要保留开头的零。不要在 URL 查询参数里放验证码或密码。

注册：点击创建账号 → 填邮箱并发送验证码 → 查看真实邮箱 → 填入同一邮箱最新的注册验证码及密码 → 注册进入聊天。

找回：点击忘记密码 → 填已验证邮箱并发送验证码 → 填入重置用途验证码及两次新密码 → 重置成功返回登录 → 用用户名和新密码登录。

### 发送状态与隐私

为避免通过响应和等待 SMTP 的耗时探测账号是否存在，申请接口对符合条件和不符合条件的邮箱统一返回 202 和相同提示。邮件投递在响应之后进行：注册仅给未占用邮箱发送，找回仅给已验证邮箱发送。

202 仅表示已受理，不表示 SMTP 认证、投递或收件箱送达成功。配置已填但投递失败时，后台把记录设为 failed 并记录脱敏告警。前端提示检查垃圾邮件、邮箱和用途，等待后可重新申请。

本地版使用进程内后台任务，不是持久消息队列。服务器在投递前退出时，申请不会保证恢复投递；用户需要等待发送间隔后重新申请。SMTP 接受但回执超时也可能造成收到不可用验证码，应以最新一次成功申请为准。

### 限流和错误

- 每个验证码默认最多核对 5 次；错误计数不会因接口报错被回滚。
- 同邮箱同用途默认 60 秒重发间隔；邮箱每小时 5 次申请，连接 IP 每小时 20 次，应用每小时 100 次。
- 核验额外限制同邮箱每 5 分钟 20 次、同连接 IP 每 5 分钟 40 次。
- 注册和登录原有的限流继续生效。
- 400 表示验证码不可用；409 表示注册信息冲突；422 表示格式错误；429 返回 Retry-After；503 表示邮件配置不可用。
- 忘记密码申请不会锁定账号或修改密码，只有核验成功才会改密；成功后会尽力发送不含密码的通知邮件。

## 5. 数据库已经做了什么

完整 SQL 在 [schema.sql](D:/code/project_python/wen_da/backend/sql/schema.sql)，旧账号迁移在 [001_email_verification.sql](D:/code/project_python/wen_da/backend/sql/migrations/001_email_verification.sql)。

users 新增 email、email_verified_at、auth_version；新增 email_verifications 与 schema_migrations。原来的 users、sessions、auth_attempts 继续使用，没有重建账号或写入默认密码。

验证码保存的是 HMAC 摘要，绑定记录 ID、邮箱和用途，摘要密钥不在数据库中。注册写入与验证码消耗是原子操作；密码重置、令牌撤销和验证码消耗也是原子操作。auth_version 阻止正在用旧密码验证的并发登录在改密之后重新建立会话。

邮箱规范化只处理标准形式和域名大小写，本地部分保留，不擅自合并点号或加号别名。数据库采用相同规则进行唯一性检查。

## 7. 测试

后端运行 `python -m pytest backend/tests`，前端运行 `pnpm test`、`pnpm build`、`pnpm test:e2e` 和 `pnpm test:integration`。

测试使用临时数据库、模拟邮件和模拟模型；HTTP 联调使用真实浏览器、Cookie 和 FastAPI，不向真实邮箱发送验证码，没有从正式接口读取验证码的调试后门。

自动化测试通过不等于真实 SMTP 已配置或收件箱已收到邮件；真实发件联调需要用户填写自己的服务配置后单独验证。
